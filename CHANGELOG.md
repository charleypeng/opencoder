## [Unreleased]

### Added

- Tauri 2 + SolidJS project scaffold with devtools gated to debug builds (TASK-M0-01)
- Design tokens and Tailwind CSS v4 base with light/dark theme switching (TASK-M0-02)
- OpenAPI type generation pipeline: `openapi-typescript` from the version-locked contract, with drift detection (TASK-M0-03)
- Mock OpenCode Server REST skeleton: health / project / session endpoints, fault injection, optional Basic Auth (TASK-M0-04)
- Mock Server SSE streams and scenario scripts: happy-chat, permission-flow, question-flow, sse-drop (TASK-M0-05)
- Real-response sample fixtures with a recording script and schema validation (TASK-M0-06)
- CI pipelines and the `pnpm verify` quality gate, with husky + lint-staged pre-commit hooks (TASK-M0-07)
- Bilingual engineering docs skeleton: README / CHANGELOG (en + zh) and CONTRIBUTING (TASK-M0-08)
- Rust REST transport channel (reqwest/rustls, Basic Auth, timeouts, cancellation, error classification) and a TS ApiClient facade with dual invoke/fetch transports (TASK-M1-01)
- Rust SSE subscription manager (line parsing across chunk boundaries, `tui.*`/`workspace.*` event filtering, 16ms batched Channel pushes, exponential-backoff reconnect, heartbeat timeout) with a TS subscription facade over tauri Channels (TASK-M1-02)
- Rust server registry: persistent CRUD commands (`list_servers`, `add_server`, `update_server`, `remove_server`, `resolve_server_base_url`) backed by tauri-plugin-store, with `servers-changed` sync events; transport channels now resolve server base URLs through the registry (TASK-M1-03)
- Rust health monitor: per-server 15s `GET /global/health` polling through the REST transport, latency/version tracking, 3-strike down detection with recovery and `server-health` events to the frontend, plus a SolidJS connection store mirroring the snapshots (TASK-M1-04)
- Add Server wizard: name/URL/optional-auth form with URL normalization, a live "Test connection" probe (version + latency), a plain-HTTP risk warning, and save through the registry commands, with typed TS wrappers for the server registry commands (TASK-M1-05)
- Server navigation home: app landing page with a responsive server card grid (name/URL/status light/version/latency/last connected), live updates via `servers-changed` and `server-health` events, a context menu (and menu button) for edit / reconnect / delete with confirmation, an edit mode for the Add Server wizard (`update_server`), and an empty state guide (TASK-M1-06)
- mDNS LAN auto-discovery: Rust scan of `_opencode._tcp` (plus the `_http._tcp` advertisement of `opencode serve --mdns`) with per-instance dedupe, `server-discovered` events and idempotent `start_mdns_discovery` / `stop_mdns_discovery` / `get_discovered_servers` commands, silent degradation when the LAN is unreachable, plus a "Nearby servers" section in the Add Server wizard with one-click prefill and auto-probe (TASK-M1-07)
- Server workspace shell: three-column desktop skeleton (server rail with per-server health dots and ⌘/Ctrl+1..9 quick switching, sidebar, main pane) replacing the placeholder view, an active-server registry store that scopes the context for per-server stores (isolation on switch), SSE disconnect hook point on leave (wired in M2), and a mobile shell placeholder for M7 (TASK-M1-08)
- Credential re-auth and connection error handling: classified error copy (`errorTitle`/`errorDetail`) centralized in `services/errors.ts` for 401/network/timeout/5xx/invalid-url/cancelled/invalid-response, a dismissable `ErrorBanner` for ServerHome load and reconnect failures, a 401-triggered credential re-entry dialog that verifies new credentials with a probe before persisting them (`update_server`), and TS-side probe response validation rejecting non-health payloads as `invalid_response` (TASK-M1-09)
- Project/session/message domain service layer: factory-form typed services (`createProjectService` / `createSessionService` / `createMessageService`) over the ApiClient covering `/project`, `/project/current`, `/path`, session CRUD (`/session` GET/POST, `/session/{id}` GET/PATCH/DELETE), `/session/status`, message history with `limit`/`before` pagination (`/session/{id}/message`), `prompt_async` and `abort`, with schema-derived types and ApiError passthrough; mock server extended with `/path`, `/session/status`, create/update/delete, `prompt_async` (204), `abort`, and `limit`-aware message pagination, plus fixture fallback across fixture roots (TASK-M2-01)
- SSE event routing and normalized stores: per-server session store (list/order/statuses/active id), normalized messages store (`parts: Record<id, Part>` + `order`, O(1) delta appends, text stub on delta-before-part, part/message removal), project store (project list + active directory), and the `events.ts` router mapping `session.*` / `message.*` / `message.part.*` events into the stores, with `syncAll` full re-sync (session list + status map + projects + current directory) triggered by `server.connected` via `subscribeToServerEvents`, driven by the happy-chat mock scenario in L1 tests (TASK-M2-02)
- Project/folder switcher: sidebar top-section dropdown (project name + path, current highlighted, "Recent" per-server memory in localStorage capped at 5) over `/project` + `/project/current`; switching a project switches the global `?directory=` context (explicit per-call directories now win over the global one), rebuilds the per-directory SSE stream in DesktopShell (unsubscribe + resubscribe + re-sync, with session/message state reset so sessions and messages never mix across directories), routes `project.updated` / `project.directories.updated` project-list refreshes, and extends the mock server with a dual-project fixture (directory-aware `/session` and `/project/current`, isolated labs session list) (TASK-M2-03)
- Session list with time grouping and status badges: the sidebar's lower section renders the server's sessions bucketed by local time (Today / Yesterday / This Week / Earlier, Monday start, DST-safe boundaries) with per-session status badges (busy/retry spinner, idle dot, error red dot with message tooltip) driven live by the SSE-fed stores, a local case-insensitive search filter over title/slug with no-match and no-sessions empty states, the active-session highlight, row selection wiring (`setActiveSession` + callback), a disabled hover-actions "⋯" stub (rename/delete wired in M2-05), and virtual-scroll preparation notes; DesktopShell mounts the list in the sidebar and its main placeholder echoes the selected session id until the chat view lands in M2-06/08 (TASK-M2-04)
- Session create/rename/delete: a "+ New session" button (sidebar header + empty state) creates an empty session over `POST /session` and opens it, a per-row actions menu replaces the M2-04 stub with Rename (prefilled dialog, Enter submits / Esc cancels, `PATCH /session/{id}`) and Delete (second confirmation dialog, `DELETE /session/{id}`), all mutations apply to the store immediately with rollback to the captured original on failure plus inline (dialogs) / banner (create) error surfacing; DesktopShell's main placeholder is now driven by the store's active session id (TASK-M2-05)
- Message history rendering (v1): the main pane's chat transcript (`src/features/messages/`) fetches `GET /session/{id}/message` history on mount / session change and merges it into the normalized messages store (per-message infos added as `infos: Record<id, Message>` alongside the legacy single-info slot), rendering user bubbles right-aligned and accent-tinted and assistant bubbles left-aligned with hh:mm timestamps; parts render through `TextPart` (plain pre-wrapped text), `ReasoningPart` (folded by default with preview + chevron expand) and `ToolPart` (v1 card: tool name, pending/running/completed/error icon + label, expandable pretty-JSON input and raw output/error sections); unsupported part types are skipped gracefully; loading / empty / inline error + retry states, a streaming fallback that renders part stubs without message info as assistant, and auto-scroll that pins the bottom while the user is near it, pauses when scrolling up and offers a "New messages" jump button; DesktopShell mounts the list for the active session (placeholder only when none) (TASK-M2-06)
- Markdown rendering and code highlighting: text parts render through a markdown-it pipeline (GFM: tables, strikethrough, task lists, linkify, typographer) with raw HTML disabled and external links rewritten to open in a new tab (`target="_blank"` + `rel="noopener noreferrer"`), followed by a DOMPurify pass (allowlists extended for Shiki styles, task-list checkboxes and link targets); fenced code blocks hydrate through a lazy Shiki singleton (common languages preloaded, other bundled packs load on demand via `loadLanguage`, plain escaped `<pre>` fallback on any highlighting failure) with a language label and copy button (Clipboard API with `execCommand` fallback, "Copied!" feedback) per block; markdown body styles (headings, tables, task lists, blockquotes, inline code, code fences) built on the design tokens; security test cases cover script/onerror/javascript:/data: injection at both layers plus a complex-markdown fixture (TASK-M2-07)
- Message input and async send: a composer (`src/features/sessions/PromptBox.tsx`) pinned below the message list with an auto-growing textarea (up to ~10 lines), ⌘/Ctrl+Enter to send (plain Enter inserts a newline), ↑ on an empty input recalling and cycling the per-server prompt history (in-memory, capped at 20, most recent first, ↓/Esc to navigate back), an optimistic user message insert (local `local-*` ids, session agent/model mapped onto the user message schema) cleared immediately with a rollback + inline error banner on `POST /session/{id}/prompt_async` failure, a send lock while the POST is in flight plus a store-status-driven input lock (busy/retry: disabled input, "Generating…" placeholder, thin top progress bar; Esc abort lands in M2-10), and a disabled attachment button placeholder (M3); DesktopShell mounts the composer for the active session; L2 tests cover the send/keyboard/history/lock/failure flows plus a full-chain case (optimistic send driven through the happy-chat SSE scenario to the rendered user + assistant bubbles; E2E E03 lands with the M10 infra) (TASK-M2-08)
- Streaming incremental render pipeline: the messages store grows a `messageParts` grouping map (message id -> ordered part ids, replaced wholesale only when part membership changes) and a per-session `lastDeltaAt` streaming timestamp, plus `applyMessageBatch` applying a whole history payload in ONE produce pass; the transcript renders through a hand-written virtual list (`createVirtualList` — fixed estimate + measured heights, ResizeObserver re-measurement for growing rows, overscan, `scrollToIndex`) that mounts only the visible slice of long transcripts, per-message `MessageBubble` components subscribing to their own info/parts so a delta re-renders exactly one part row (the M2-06 regroup-on-every-delta re-render is gone), a breathing typing caret (`TypingCursor`) appended inline to the last rendered token of the streaming message, driven by a `useStreamingIndicator` hook (busy status + 5s delta window with a 1s ticker), a thin indeterminate progress bar at the top of the chat area while the session generates (the M2-08 PromptBox bar is removed — single source: session busy), and auto-scroll follow/pause/jump preserved on top of the virtualizer; L1 store tests cover grouping identity (text deltas never touch `messageParts`), batch correctness/reconciliation and `lastDeltaAt`, plus a 1000-delta benchmark; L2 covers bubble-level fine-grained re-rendering (sibling DOM nodes untouched), virtualization row counts, the progress bar and caret lifecycle with fake timers; a perf benchmark suite (`perf.bench.test.tsx`) bounds the virtual list (1000 rows x 1000 scroll positions), a 300-message transcript render and per-token delta cost (TASK-M2-09)
- Generation abort and error handling: while a session is generating (busy/retry status) the composer replaces Send with a Stop button (square danger icon, local in-flight lock collapses double clicks) that POSTs `/session/{id}/abort`, and Esc triggers the same abort from anywhere via a window-level listener (the disabled textarea cannot receive keys itself); an abort failure surfaces as the composer's inline banner and the Send button returns when the server's `session.status` idle event lands (store-driven input auto-recovery); `session.error` events render as a dismissable banner between the message list and the composer (`SessionErrorBanner`) with classified copy — `errorTitle`/`errorDetail` gained a rate-limit classification (status 429 or "rate limit"/"429" message hints -> "Rate limited — try again shortly") — an expandable "Show details" raw-message section, and a Retry action that re-sends the last prompt from the per-server history through the shared `sendPrompt` pipeline (extracted from PromptBox, used by both composer and banner; a failed re-send re-arms the banner with the classified error, a successful one dismisses it); the banner is derived from the store status entry so any replacement status (idle/busy) auto-hides it, and the session store grows a `dismissSessionError` action reverting an error status to idle; L2 tests cover stop/Esc/abort-failure/idle-restore, banner render/dismiss/auto-hide/retry (incl. no-double-retry) and rate-limit copy, L1 tests cover `dismissSessionError`, `getLastPrompt` and the sendPrompt pipeline (E2E E04 lands with the M10 infra) (TASK-M2-10)
- Full tool-call state rendering: per-tool cards (bash terminal view with prompt/exit code, edit inline diff preview, read/write code blocks, glob/grep result lists with count badges, generic JSON fallback) behind a tool registry with a component-per-tool dispatch; a complete four-state machine (pending pulsing clock / running spinner with a CSS shimmer sweep and a live ticking elapsed time with interval cleanup / completed check with measured or metadata duration / failed cross with the error message in danger styling); collapsible raw-input disclosure and copyable output with "Copied!" feedback per card; the all-parts fixture extended to every tool family and all four states, plus L2 snapshot coverage for every tool card (TASK-M3-01)
- File/patch/snapshot part rendering: file attachment cards (mime-derived image/text/file icon, name with URL-basename fallback, click-to-expand inline preview — base64 data-URL images or collapsible text blocks — from the part's inline source text only, never loading remote URLs, with a "Content unavailable" note when the part carries no content), patch cards (short commit-hash badge, total file count, one row per patched file as jump-to-diff placeholders wired through an `onOpenDiff` callback for M4), and snapshot marker chips (camera icon + short snapshot id, inert with an M6 revert tooltip); all three wired into the MessageBubble part dispatch, with L2 tests and fixture snapshots for each part type plus an all-parts-fixture bubble render (TASK-M3-02)
- Step/subtask/agent part rendering: step boundaries as thin dividers ("Step" label plus the short start-snapshot id when present) and "Step complete" meta rows (finish reason, formatted token count with k/M rounding, USD cost), subtask cards (prompt header with a shared agent chip, expandable description plus model/command meta rows, and an M6 child-session placeholder note — the 1.18.11 schema carries no status or child-session id, so no status badge or navigation yet), and agent mention chips (accent tone with a robot icon and a mention-source tooltip); all four wired into the MessageBubble part dispatch, `formatTokens`/`formatUSD` unit cases, L2 tests and fixture snapshots for each part type, the all-parts fixture extended with a second step pair and an agent part for the multi-step hierarchy, plus an all-parts-fixture bubble render (TASK-M3-03)
- Retry and compaction notice rendering: retry parts render as system chips with a refresh icon, the attempt count ("Retrying (attempt N)") and the failure reason (danger styling for rate-limit errors — 429 status or "rate limit"/"429" message hints, faint otherwise); a countdown label ticks down "next attempt in Xs" once per second when the caller provides a `retryAt` epoch (the 1.18.11 schema carries no scheduling field), falls back to a static "Retrying…" without timing data and cleans up its interval on dispose; compaction parts render as "Context compacted" system lines with a compress icon, expanding to the schema-provided detail (auto/manual mode, overflow flag, tail part id) and standing alone without a toggle when the part carries no detail fields; both wired into the MessageBubble part dispatch, with L2 tests (attempt/error display, rate-limit classification, countdown ticking + zero fallback + cleanup under fake timers, expand/collapse, line-only fallback) and fixture snapshots, plus all-parts-fixture bubble and list renders (TASK-M3-04)
