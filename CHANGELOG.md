# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Composer task panel (feat(sessions)): the todo list and sub-agent child sessions now live in a collapsible panel above the chat composer — it auto-expands when tasks or subtasks appear, auto-collapses when everything completes, supports manual collapse/expand (header chevron or the chat header's Tasks button), groups children under an expandable "N agents" section, and shows a back affordance to return to the parent task while inside a child session. Replaces the right-side todo drawer. (sessions)

### Fixed

- Composer shortcuts honor customizations (fix(settings)): the chat input's local keys — send message (⌘/Ctrl+Enter by default), agent cycle (Tab) and last-prompt recall (↑) — now read the shortcut registry's effective combos instead of being hardcoded, so remapping them in Settings actually takes effect (e.g. sendMessage set to a bare Enter sends on Enter). (settings)

## [1.0.1] - 2026-08-16

### Fixed

- Desktop prefs survive restarts (fix(desktop)): the close-to-tray flag and the global summon accelerator are now persisted in the app store (Rust side) instead of relying on the webview's localStorage, and restored at startup — custom shortcuts and the tray behaviour no longer reset on relaunch. (desktop)

- Tray lifecycle follows close-to-tray (fix(desktop)): the tray icon now exists only while "close to tray" is enabled (toggling it off removes the icon, and it is not built at startup unless persisted on); with the setting off, closing the main window fully quits the app instead of lingering in the background. (desktop)

### Fixed

### Fixed

- Pet click-through state fix (fix(pet)): removed the pet's right-click settings menu and synchronized the reset performed when the pet is shown again, so the visible click-through indicator matches the actual Tauri pointer-event state. (pet)

- Markdown source toggle fix (fix(files)): selecting "View source" from a markdown tab's context menu now actually switches the active content from the rendered preview to the source view. The menu now uses the shared ContextMenu component and safely captures the tab path before unmounting. (files)

- Workspace & session management fixes (fix(sessions)): five bugs in the workspace/session flow are resolved. (1) The default workspace now always renders in the tree — a default picked at runtime (onboarding or Settings) refreshes immediately through a storage-change event; previously a memo cached the first read and never saw post-mount writes, so the picked default did not appear until a remount. (2) New-session (header "+" and folder [+]) opens the new chat in the chat pane — the main view switches back to Chat on selection, and the context rebuild restores the active session after the re-sync even when it is not (yet) in the fresh session list (a brand-new session may lag the first GET /session snapshot; requiring list membership left the chat on the "Select a session" placeholder). (3) Cross-directory session picks and new-session flows no longer leave the chat empty: the per-directory context rebuild preserves the active session across the re-sync (resetSessions used to wipe activeSessionId, racing selectSession's setActiveSession — untrack keeps the capture out of the effect's deps). (4) Removing a server now clears its local workspace/default/recent-project memory so re-adding the same server starts fresh. (5) The workspace ⋯ "View folder" command shows the picked directory's files AND switches the session context there — every file request (subtree expansion, file content, git status) is routed by the active directory, so browsing a folder without switching the context made the server answer for the wrong workspace: subdirectories did not expand (UnknownError), file content came back empty. The file tree now also sends the browsed directory explicitly on subtree fetches and status requests. (6) The workspace tree's cross-directory session listing (GET /session?roots=true) no longer inherits the global active-directory injection — it used to narrow the listing to the current folder, so the other workspaces' sessions silently disappeared from the tree after switching contexts. (7) The tree snapshot is now refreshed PER known workspace: opencode's GET /session without a directory returns only the global (root) sessions, so per-directory workspaces (e.g. an added folder that the server has no project record for) used to lose their sessions on every refresh — each explicit/default workspace is queried with its own ?directory=. (8) "Remove workspace" now sticks for the active folder: the un-hide effect reacts only to the current directory changing (untrack), and removing the current workspace clears the context so the auto-enter picks the next visible folder — previously the effect re-ran on the hidden-set write and immediately restored the folder the user just removed. (sessions)

- Selecting a workspace with no sessions now creates one automatically (fix(sessions)): picking any entry in the project switcher — including re-selecting the DEFAULT workspace — lists the folder's sessions in its own context and, when it has none, creates a session in it and opens it; workspaces with sessions select the first one instead, and failures stay silent (the per-directory SSE re-sync settles the list). (sessions)

- File viewer markdown preview (feat(files)): `.md` and `.markdown` files now render as formatted HTML by default (same sanitized markdown-it + DOMPurify pipeline as chat messages), instead of syntax-highlighted source. Right-clicking a markdown tab opens a context menu with "View source" / "View rendered" to toggle between the raw text and the formatted preview; the choice is remembered per-path across view switches. (files)

- VCS change-row click (feat(vcs)): clicking a file in the VCS changes list now opens that single file's diff patch in a focused sub-view (previously the rows were non-interactive; clicking a file did nothing). The full workspace diff is still available via the "Workspace diff" button. (vcs)

- Diff stats coloring (fix(vcs)): the +N -M addition/deletion counts in both the VCS change list and the diff file headers now render with distinct colors — green for additions, red for deletions — instead of a single muted gray. (vcs)

- Settings toggle switch fix (fix(settings)): all toggle switches across the settings dialog (Desktop, Notifications, Servers, Appearance, Diagnostics) had a positioning bug where the knob drifted to a wrong position because the `absolute` positioning lacked a `left` anchor — the browser placed the knob at its static position which varied with the button's content. Fixed by adding `left-0.5` to the knob and removing the redundant `translate-x-0.5` from the OFF state; the ON state's `translate-x-5` now correctly slides the knob to the right edge. (settings)

- Workspace-tree & session fixes (fix(sessions)): four remaining bugs from the workspace redesign are resolved. (1) The DEFAULT workspace's sessions now render under its row when expanded — previously the default folder rendered only its header, so the count badge showed N sessions that could never be expanded into view. (2) The active session now survives ANY session-store reset, not just the rebuild's own re-sync: a `server.connected` SSE reconnect (the real server reconnects idle streams) resets the session bucket and used to leave the chat on the "Select a session" placeholder even right after creating a session; the session store now keeps the last selection as a restore candidate (armed by setActiveSession, disarmed when that session is deleted) and the shell re-selects it after every reset — deleting the active session still clears the chat. (3) Re-syncs no longer overwrite the client's active directory with the server's per-directory /project/current — for folders that are not themselves project roots that response reports a PARENT worktree, which churned the SSE context (rebuild → re-sync → setCurrent → rebuild) and routed file/session requests to the wrong workspace, surfacing as "Unexpected server error" (UnknownError) when expanding a folder in the file tree; the directory is now seeded only when unset, and a fresh server entry lands in its DEFAULT workspace (auto-enter prefers the persisted default over the most recently used folder). (4) Deleting a session now removes its row from the workspace tree — the tree's snapshot refresh replaced the list with a plain object that Solid's setStore MERGED into the existing one, so a deleted session never left the snapshot (the row lingered until restart); the snapshot is now replaced wholesale. (sessions)

- Accessibility fixes for the workspace tree (fix(sessions)): session rows no longer nest interactive controls (axe nested-interactive — the row wrapper is non-interactive and the focusable row button + ⋯ action button are siblings, ported from SessionList), and the DesktopShell a11y sweep seeds the onboarding flag so the first-run default-workspace dialog (which hides the app behind it) no longer makes the axe run vacuous. (sessions)

- The header "+" now creates a session directly in the current working directory (fix(sessions)): the project-directory picker no longer intercepts the new-session flow — choosing a folder happens through the project switcher's new add-directory flow; the filepicker dialog and its i18n keys are gone. (sessions)

### Removed

### Fixed

- Chat rows overlap and flicker while streaming or scrolling (fix(messages)): rows were rendered by an UNKEYED For, so any measured height change (async Shiki code-fence hydration grows a row after its placeholder was measured) re-created the whole row subtree — the row shrank and grew between placeholder and hydrated heights in a ResizeObserver feedback loop, rows piled on top of each other (user bubbles rendered over assistant text), and the bottom of the transcript never settled (the "jump to bottom" target lagged ~110px per affected row). Rows are now keyed by message id (solid-primitives `Key`), so a re-measure only moves `style.top` and the bubble DOM (including hydrated code fences) survives; the loop is gone and the transcript reaches a stable bottom. Regression test simulates a ResizeObserver height change and asserts row DOM identity. (messages)

- Thinking content sometimes truncated (fix(messages)): history-page loads (applyMessageBatch) OVERWROTE existing parts unconditionally — a long reasoning text already accumulated from SSE deltas could be cut back to a shorter server snapshot (the history-page vs streaming race when opening a session). History pages now only insert MISSING parts (`overwrite=false`); streamed text is never clobbered by a snapshot, and `lastDeltaAt` bumps only on real changes. Two regression tests cover "short snapshot does not truncate streamed text" and "missing parts still fill in". (messages)

- Opening the file tree answered 400 BadRequest "Missing key at [\"path\"]" (fix(files)): `GET /file` requires the `path` query (openapi required; real opencode servers validate it), but FileTree's root load called `tree()` without it — rejected by real servers while the static mock fixture hid the bug. The root load now passes `path=""` explicitly (the root-listing convention); the mock's `/file` is now a dynamic route answering the same 400 without the key, asserted in the self-test so client regressions cannot hide behind a lenient fixture again. (files)

- Reasoning fold cannot be expanded during streaming (fix(messages)): the part dispatch memo returned a fresh component element every time a `message.part.updated` event replaced the part object, re-creating the reasoning part and resetting its expanded state to collapsed — the fold opened and instantly closed again while the agent was generating. The memo's equality now compares the rendered component type instead of the element identity, so same-type part replacements keep the mounted component instance and its local state. Superseded by the entry below (the equality fix kept the old element while the component re-ran, which broke toggling after streaming ended). (messages)

- Mock provider catalog reflects added providers (fix(mock)): the new-user walkthrough (TASK-S1-04) verified the S1-01/02/03 features end to end — add server → rail settings entry → Models default picker (config default shown, "Local default" chip after a pick, Clear works) → theme light (data-theme flips) → language zh (active state) → AddProviderDialog opens/submits with PATCH /global/config writing `provider.myllm` — but AFTER adding, the new provider did NOT appear in the Providers list: GET /provider served a STATIC fixture while the real opencode server loads config-declared providers into the catalog. The mock's GET /provider is now a dynamic handler that merges `globalConfig.provider` entries into the fixture catalog (synthesizing a Provider with `source: "config"`, env/options from the ProviderConfig and an empty models record — "Not connected" until a key is set), preserving the fixture's `default`/`connected` records; the client code is untouched (it already refetches the catalog after add). The mock self-test asserts the merged catalog (added id present, static ids + default/connected preserved); walkthrough results recorded in docs/plans/settings-center.md. (TASK-S1-04)

- Reasoning fold stays toggleable after streaming ends (fix(messages)): the part dispatch memo cached a JSX ELEMENT, so every `message.part.updated` replacement re-ran the part component (fresh signals) while the memo's custom equality kept the OLD element — the DOM kept listening to the old signal, so a click after streaming ended updated a signal the DOM was no longer bound to (the fold could not be collapsed; part text deltas also desynced). The memo now caches the rendered COMPONENT TYPE and mounts it through Solid's `Dynamic`, which updates props reactively without re-creating the instance; a same-type part replacement keeps the mounted component (and its local state), and a genuine type change still swaps the component. Regression test: expand mid-stream → part replaced → stream ends → collapse/expand still works. (messages)

- Code fences now follow the app theme (fix(messages)): the Shiki highlighter was hard-wired to `github-dark`, so code blocks kept dark backgrounds and light token colors in light mode. The highlighter now loads both `github-dark` and `github-light` and picks the theme from `<html data-theme>` (dark/oled → dark, light → light), and MarkdownText watches the theme attribute to re-highlight already-hydrated fences on switch. Tests cover the theme selection and the re-highlight on theme change. (messages)

- Part toggle buttons no longer paint a hover background (fix(chat)): the expand/collapse buttons on reasoning, tool, subtask, compaction and file parts dropped `hover:bg-accent-soft` — the hover tint read as a shadow block in light mode; keyboard focus styling (`focus:bg-accent-soft`) is kept. (chat-ui)

- Context menu hover highlight stays inside the panel's rounded corners (fix(ui)): the glass menu panel has a large radius (--r-xl) while row highlights use a small one, so hovering a row painted a highlight block that poked out of the rounded corners. Rows are now clipped to the panel radius (the shadow still lives on the outer panel); the fix applies to the menu and its submenus. (chat-ui)

- Patch part rows expand an inline diff (feat(messages)): clicking a patched file row in the patch card previously did nothing (the onOpenDiff hook was never wired). Each row now toggles an inline diff fetched once per card from `GET /session/{id}/diff` (message-filtered) and rendered with the shared DiffFileGroup — line-colored unified rows with the file's +adds -dels stats and status chip, plus loading / error / empty states; re-expanding uses the cached payload. (messages)

- App shell pinned on every platform (feat(ui)): html/body/#root are locked to the viewport with `overflow: hidden` and `overscroll-behavior: none`, and every element inherits `overscroll-behavior: none` — the app no longer rubber-bands at the scroll ends (iOS bounce, desktop WebView overscroll glow / scroll chaining), so it feels like a desktop app instead of a web page. (TASK-UI-01)

- Server OAuth (RFC 9728) for OAuth-protected servers (feat(servers)): servers protected by an OAuth resource server (Cloudflare Access managed OAuth is the reference flow) can now be authorized from the client — the Add Server probe discovers `/.well-known/oauth-authorization-server`, the consent dialog builds a PKCE authorization request (S256 challenge, state; the verifier never leaves the process), opens the system browser and exchanges the pasted code for tokens; the access token is injected as `Authorization: Bearer` into every request (it wins over Basic credentials) and the refresh token rotates the access token on demand.
