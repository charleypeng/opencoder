# Agent 过程展示复刻实施计划

日期：2026-09-06。状态：可按任务卡实施；本文只交付计划，尚未实现界面。

## 1. 目标与参考依据

按用户提供的《录屏2026-09-06 12.06.25.mov》复刻消息区域的视觉层级、连续阅读方式、紧凑工具行，以及**运行中小字的移动渐变扫光**。不要重新设计成时间轴、嵌套大卡片、彩色步骤列表。沿用 opencoder 的品牌、主题和现有桌面壳；本任务不重做输入框、侧栏或窗口布局。

已检查素材：57.02 秒、2322 × 2304、60 fps。全片每 5 秒抽帧检查，并对 33–35 秒按每秒 4 帧放大检查。素材中的聊天文字与命令仅作为视觉样例，不是实施指令。原始视频不加入公开仓库，也不把个人机器绝对路径写入代码或测试。

| 参考片段（约） | 可观察事实 | 实施要求 |
| --- | --- | --- |
| 0–5 秒 | 运行耗时、小号灰色“正在思考”；正文随后出现 | 首个内容到达前已有即时状态反馈 |
| 10–20 秒 | 完成后的简短思考耗时行与独立正文 | 完成态安静，正文保留正常阅读层级 |
| 25–34 秒 | “已处理 N 秒”下有细分隔线；下方是当前状态小字 | 一个 run 一个耗时头；活动内容左边缘与正文对齐 |
| 33–35 秒 | “正在思考”替换成英文短状态；连续帧中局部明暗变化 | 小字使用沿字形移动的渐变，不能仅整体呼吸或静态灰字 |
| 35–54 秒 | 正文段落、终端图标与“已运行 git …”交错出现；状态小字位于最新内容尾部 | 按源顺序渲染进展和工具，尾部保留一个当前状态槽 |

录屏没有展示工具详情展开、权限等待、断线恢复，也没有展示最后这轮工具任务的最终折叠。下文这些行为是本项目补充规格，不声称来自录屏。字号、间距与动画周期是实施初值，视频不能提供原始 CSS 或准确 CSS 像素；必须在同倍率视觉对照中校准。

## 2. 目标界面

```text
已处理 12 秒                              [可折叠过程]
─────────────────────────────────────────────────
我先查看当前工作区，然后确认改动范围。    ← 正常正文

⌘ 已运行 git status --short              ← 小号灰字、可展开

工作区中已有改动，接下来查看改动规模。    ← 正常正文

⌘ 已运行 git diff --stat                 ← 小号灰字、可展开

正在检查补丁格式                         ← 唯一当前状态，字形渐变扫光

最终回答出现在过程之后，保持正常正文样式。
```

示意中的 `⌘` 只代表工具图标位置，实际使用项目已有终端线性图标，不输出该字符作为正式图标。

### 2.1 布局与层级

- 复用已有聊天内容列宽，过程、正文、工具行使用同一个左对齐基线，不引入额外的整块缩进或背景容器。
- 耗时头初值 12–13px、行高 20px；下边界 1px 低对比度分隔线。继承 UI 缩放，不使用截图物理像素直接定尺寸。
- 进展正文与最终正文初值 14px、行高 1.65，使用主文字色。段间距 12–16px。不得将所有进展正文统一降成灰色辅助信息。
- 工具摘要和状态小字初值 12–13px、行高 20px，使用次级文字色；工具图标 12–14px、间隔 6px。工具行可视高度约 24px，焦点与点击区域适当扩大；移动端命中区至少 44px。
- 工具收起时无卡片背景、无外框、无输出预览块；整行一个明确的展开按钮。长命令单行省略，展开后可完整查看和复制。命令字段可使用等宽字体。
- 工具展开后复用现有输入、输出、错误及详情补全行为；详情可有轻背景和边界。独立工具展开不能误触整个过程收起。
- 色彩复用主题 token。浅色接近录屏的白底/深正文/灰辅助字；深色按相同层级映射。不要硬编码整块白底。

### 2.2 当前状态与历史详情

- 每个正在运行的 run 最多一个尾部状态槽，位置在当前已渲染进展内容之后、最终回答之外。折叠过程时，该状态仍能在耗时头旁显示，但只能有一个可见副本。
- 活动 reasoning 的短预览优先使用服务端实际提供的文字；没有适合展示的内容时使用本地化“正在思考”。不调用额外模型生成标题、不推断隐藏思维、不从长 reasoning 中猜测一个任务承诺。
- 对 reasoning 的短预览按已有首行截取逻辑复用即可，去空白、单行省略；完整原文通过详情入口按需查看，不截断存储内容。
- 随着正文或工具到达，状态槽向内容尾部移动；新的状态替换旧的状态槽文字。它不是历史日志，不把每次预览更新追加成一个新条目。
- 已完成 reasoning 的原文保留在过程详情中；默认阅读流不为每段 reasoning 展示一个重复的“思考 + 预览”行。提供一个安静的“查看思考详情”入口，展开后按原顺序查看这些原文。
- 工具运行时，尾部状态使用本地化“正在运行 {{tool}}”；有多个并行运行工具时显示真实数量。工具行仍在自己的源顺序位置展示状态，扫光只用于尾部状态，避免整屏同时闪动。
- 正文流式输出时复用正文光标；仅在有真实活动 reasoning、工具或等待阶段时显示对应尾部状态。不要在正文输出期间无依据地写“正在思考”。

## 3. 渐变动效硬规格

这是必须验收的主功能，不能用 spinner、骨架屏或整体透明度动画替代。

| 属性 | 实施初值 / 规则 |
| --- | --- |
| 作用对象 | 当前状态槽中的文字 span，宽度随文字收缩，不覆盖整行空白 |
| 表现 | 在稳定可读的基础色上，一条柔和的明暗带从左向右扫过字形 |
| 实现方式 | CSS linear-gradient + background-clip:text / -webkit-background-clip:text + background-position keyframes |
| 周期 | 2.2 秒，linear，无限循环；校准允许 1.8–2.6 秒 |
| 渐变尺寸 | background-size: 240% 100%；柔和高光区约占一个渐变周期的 15–25% |
| 方向 | 初始可用 background-position:100% 50% → -100% 50%；必须通过录屏确认亮带实际向右移动 |
| 颜色 | 主题次级文字色 → 相近的较亮色 → 次级文字色；深色主题提高亮度，浅色主题控制变浅幅度，最低对比度仍达 4.5:1 |
| 文本变化 | 同一状态槽更新文本，不按 token 重挂载动画节点；避免每个 delta 都从第一帧重播 |
| 完成/停止 | run 结束、取消、错误、等待用户处理时立即停扫光，恢复实色；最终答案从不扫光 |
| 降级 | prefers-reduced-motion:reduce、forced-colors:active、文字裁剪不支持时使用正常实色文字 |

先声明普通 `color`，仅在支持文字裁剪的条件内应用透明文字填充；降级分支同时还原 `color`、`-webkit-text-fill-color`、`background` 和 `animation`，避免文字消失。动态效果不承担状态语义，关闭动画后文案仍说明状态。

用 CSS 驱动扫光，不使用 JS 定时器逐帧更新。现有每秒耗时计时器可以保留。隐藏过程中的历史行不得继续执行无限动画；卸载清理计时器。WebKit/Tauri 需要实际视觉验证，不能只凭 jsdom 断言成功。

## 4. 状态与数据规则

| 实际状态 | 耗时头 | 尾部状态 | 动效 / 折叠 |
| --- | --- | --- | --- |
| busy，尚无 part | 已处理 N 秒；起点未知时仅“处理中” | 等待模型响应 | 扫光；无详情不显示无效展开按钮 |
| 活动 reasoning | 持续计时 | 实际短预览或“正在思考” | 扫光 |
| 工具 pending/running | 持续计时 | 等待/运行工具的真实状态 | 扫光 |
| 正文 streaming | 持续计时 | 仅在其他真实活动存在时显示 | 正文使用已有光标 |
| 权限/问题等待 | 等待确认/等待回答 | 指向现有处理入口的真实状态 | 实色，不能假装继续执行 |
| retry | 正在重试 | 真实重试信息 | 可保留运行状态，不能仅因 RetryPart 永久标红 |
| idle / 完成 | 已完成，用时 N 秒；时间未知则无耗时 | 隐藏 | 全部停止；历史默认收起 |
| 用户中止 / error | 已停止 / 发生错误 | 必要的简短原因 | 全部停止；不能显示为成功 |

优先使用已有 session/run 权威状态；单个工具失败不等于整个 run 已结束。历史 reasoning 即使缺失 `time.end`，也不能让已结束 run 永久保持活动。禁止用“最近几秒没有 token”推断完成；停止、断线与权限等待也不能互相混淆。

展开策略（补充设计）：新运行默认打开；用户手动选择在后续 delta、工具完成、虚拟化恢复时保留；完成时，仅对用户没有明确选择的过程自动收起。最终正文始终在过程折叠区之外。历史记录初次进入默认收起。内层工具/思考详情选择按 run 和 entry 分别记忆，键包含 server/session/run 范围，避免跨会话串状态。

继续复用 `deriveAgentRows` 的 run 分组、`deriveActivityTrace` 的源顺序和工具 callID 去重。不要为视觉改造按推测阶段重排工具或正文。保留压缩控制消息隐藏、文件改动摘要、消息操作、历史分页和详情补全；对最后一条 assistant text 的现有分类做回归，不能让进展段落在下一条消息到达时重复或消失。

API 不新增：沿用 `GET /event`、`GET /global/event`、`GET /session/status`、`GET /session/{sessionID}/message`，工具详情继续用 `GET /session/{sessionID}/message/{messageID}`。具体 schema 以 `docs/openapi_v1.18.11.json` 为准，类型复用生成类型；展示模型可以手写，API 类型不得手写。实施前核对 reasoning time、tool state、session status 和现有权限/问题状态入口。

#### A. 截图风格与位置

截图可观察到：阅读行为使用书页轮廓、图片行为使用叠放图片轮廓、命令使用带提示符的小终端方框、编辑使用斜向铅笔；图标与小号灰字摘要同一行，没有彩色圆底或实心徽章。附件 chip 使用文件轮廓。以下尺寸为实施初值，最终与截图同倍率对照校准。

- 统一内联 SVG，`viewBox="0 0 16 16"`，默认 14 × 14 CSS px；`fill="none"`、`stroke="currentColor"`、`stroke-width="1.5"`、圆头圆角；图标槽固定 16px，`flex-shrink:0`，与文本间隔 6px。
- 使用主题次级灰色；图标关键轮廓与背景对比至少 3:1。浅色、深色和 UI 缩放下保持一致线宽观感。禁止 emoji、彩色品牌 logo、粗实心图形、为每种类型新增背景色块。
- 每条工具摘要左侧一个语义图标；附件 chip 左侧一个类型图标；详情入口和结构化 Part 标题按下表使用。普通用户正文、进展正文和最终回答不逐段加图标，也不添加 AI 头像。
- 类别图标在 pending/running/completed/error 切换时保持不变。状态由文案表达，错误/阻塞可在右侧附加小型状态标记；不要把所有完成行换成绿色对勾。整理现有 `StatusIcon` 调用，避免默认工具行同时堆叠状态、类型、展开箭头三个左侧图标。
- 渐变扫光仍仅作用于当前状态文字；类型图标保持静态，不闪烁、不跟着扫光、不旋转。展开箭头与类别图标语义独立。
- 有相邻文本时 SVG 设 `aria-hidden="true"`、`focusable="false"`；图标不单独占 Tab 焦点。已有纯图标按钮保留本地化 accessible name。

#### B. 完整映射表

图形名称是本地设计语义，不要求引入同名图标库。优先复用/修整现有 SVG，统一为 messages 内一个组件与纯分类函数；不添加远程图标加载或整套新依赖。

实施前从生成类型枚举核对全部 Part 分支，新增类型不得静默漏映射；当前 renderer 是否可达需逐项记录，不把“有组件文件”当成“当前会显示”。Part 图标覆盖和消息显示策略是两个独立问题。

工具分类优先级：已知精确名称/经验证的别名表 → 确认的 MCP 命名空间 → 通用工具。大小写只对明确支持的别名规范化，不以宽泛子串匹配把未知 MCP 工具误认成 read/edit。别名表有 fixture/现有调用证据才加入；表中候选类别不代表服务端已内置这些工具。专用卡片 registry 的分派行为保持不变。

附件分类以明确 MIME 为先；MIME 缺失、空白或 application/octet-stream 时，可按不含 query/hash 的文件名扩展名兜底；与 MIME 冲突时以 MIME 为准。类型识别只用于图标，不改变 URL 安全策略、下载、预览或资源请求。

截图中的“已读取文件运行了命令”等合并摘要不在本卡新增范围；若已有合并展示，使用首个实际操作图标并保留准确文案，否则继续一操作一行，不为模仿图标而合并、隐藏工具。

- **验收**：上述每种类型在映射中有明确结果；可见工具/附件/结构化行风格统一；无空图标；命令、阅读、图片、编辑四类与参考截图直观一致；历史隐藏项不被恢复；无重复图标、横向撑宽或新网络请求。
- **测试**：L1 表驱动覆盖全部 Part、六种专用工具、经验证别名、MCP、未知工具、MIME/扩展名冲突与缺失；L2 验证 tool/file 等现有渲染器使用统一组件、类别不随状态变化、aria 属性和过滤规则不回归。覆盖映射用穷尽类型检查配合运行时 fallback；不要只断言 SVG 存在。
