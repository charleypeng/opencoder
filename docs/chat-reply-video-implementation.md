# Chat AI 回复改版：录屏分析与 Agent 实施规格

状态：待实施。本文只定义方案，不表示产品已经完成改版。

依据：用户提供的 77.04 秒录屏（4096 × 2304）与当前消息组件源码。分析采用全片每 5 秒概览、后半段每 3 秒交互采样及 51 / 52 秒原尺寸局部帧。未读取或参考任何既有 docs 文档。录屏中的命令和回复仅作为 UI 示例，不是需要执行的指令。

本文中的秒数均为视频播放时间，取近似值。尺寸和颜色是供实施的建议值，不是从视频反推出的 CSS。没有在录屏中验证的行为会明确标为“设计决策”。

## 1. 要实现的效果

把 AI 回复做成简洁的连续阅读流：正文直接排在聊天背景上；工具调用以轻量单行穿插在正文之间；思考默认只占一行；用户点击后才展开详细信息。整个执行过程可以收起，最终回答始终可见。

视觉优先级：最终回答与对用户有价值的进展正文 > 工具操作摘要 > 思考与耗时。不要把整个回复做成灰底大卡片，不要用竖线、彩色圆点和多层缩进连接每个步骤。

本轮范围为 AI 回复区域、其执行过程、工具详情和必要的滚动适配。保留现有输入框、工作区、设置、右栏功能。录屏里的用户气泡、侧栏、模型选择器及麦克风不属于本轮复制范围。

## 2. 录屏证据与边界

| 时间 | 实际看到的内容 | 实施含义 |
| --- | --- | --- |
| 约 0–20 秒 | 普通 AI 回复直接显示一段文字，没有 AI 徽标、气泡背景、步骤容器 | 纯文本回答不制造空的执行卡片 |
| 约 20–30 秒 | 第二次请求后出现灰色“正在思考” | 等待首个内容时只展示一行轻量状态 |
| 约 30–45 秒 | “已处理 N 秒”位于回复上方；进展段落、工具提示、清单依次出现 | 正文与过程按顺序展示，不重复一份“进展摘要 + 正文” |
| 约 45–51 秒 | 英文短思考标题；“已运行 + 长命令”保持单行并省略尾部 | 思考标题与工具标题都保持紧凑 |
| 51 → 52 秒 | 命令行附近发生操作后出现 Shell 面板；标题由长命令变成“已运行命令” | 工具详情原位展开，长命令搬到详情内 |
| 约 54–66 秒 | Shell 面板收起；后续进展与另一条命令继续出现 | 工具详情不强迫全部展开，不阻断流式回复 |
| 约 69–77 秒 | 顶部变成“用时 46 秒”及折叠箭头，正文、工具行、最终结论仍可见；底部出现小型操作图标 | 完成后停止计时，保留当下阅读状态；操作区轻量化 |

证据限制：录屏没有完整演示顶层收起后的结果、错误工具、授权请求、长输出滚动、移动端、浅色主题、重启后的折叠状态。不能把这些行为写成视频已验证事实；以下章节给出 OpenCoder 的明确设计决策。

录屏可见清单，但不能据此认定它是可交互任务组件。实现时普通 Markdown 清单按内容呈现，不自动生成任务、不伪造任务进度。

## 3. 页面结构与两种模式

### 3.1 普通回复

没有 reasoning、tool、retry 等过程内容时，直接显示正文与已有消息操作。不要因为生成过文字就添加“执行完成”“0 次工具调用”等装饰。

首字到达前可显示“正在思考”；正文开始后清除此占位。若随后真的出现工具/思考事件，再切换到过程模式，不能重复已有正文。

### 3.2 含过程的回复

```text
用时 46 秒  ⌄                         ← 运行过程中为“已处理 N 秒”
──────────────────────────────────
我先检查分支和 README 的更改。          ← 对用户的进展正文，只渲染一次

⌄ 正在核对工作区                       ← 简短思考行，可单独展开
终端图标  已运行 git status …  ✓  ›     ← 工具收起态，一行

初步结果：发现一个更改文件。            ← 后续进展正文
编辑图标  已编辑 README.md  ✓  ›

检查结果如下：                         ← 最终回答，不随过程收起
……
复制 / 已有消息操作
```

顶层收起后只保留“用时 46 秒 ›”、未解决的必要交互/错误提示、最终回答与已有结果入口。过程中间正文随过程一起收起；最终回答不隐藏。顶层展开时，进展正文直接可读；思考与工具详情各自默认收起。

这是相对于当前版本有意做出的变化：不再把每段进展正文再做一次二级折叠，也不把进展摘要与完整正文同时展示。思考及工具仍按需展开。

## 4. 折叠与生命周期规则（设计决策）

| 对象/事件 | 默认行为 | 用户控制及更新行为 |
| --- | --- | --- |
| 新的含过程回复开始 | 顶层展开，正文与工具摘要实时出现 | 用户可主动收起，后续事件不能重新打开 |
| 首次加载已完成的历史回复 | 顶层收起，最终回答可见 | 点击展开恢复完整过程顺序 |
| 正在阅读的回复完成 | 冻结耗时，保留当前顶层状态 | 禁止突然收起造成页面跳动 |
| 思考条目 | 单行标题/预览，正文隐藏 | 点击当前行展开；再次点击收起 |
| 工具条目 | 单行摘要，详情隐藏 | 只切换被点击的工具；不连带其他工具 |
| 流式 delta、同 ID 对象替换 | 更新内容 | 不重置任何展开状态，不重挂载整条运行记录 |
| 虚拟列表卸载再挂载、同会话切换返回 | 恢复本次应用会话内的选择 | 使用稳定 ID 存在组件外，不能仅靠局部 signal |
| 应用重启 | 使用历史回复默认收起规则 | 不要求跨重启持久化折叠选择 |
| 等待用户授权或回答问题 | 明确显示待操作入口 | 不允许被顶层折叠完全隐藏；沿用已有交互服务 |
| 工具失败 | 行内错误图标及简短失败提示 | 详细错误按需查看，不自动展开大块日志 |

状态键必须含 serverId、sessionId、runKey；条目再含 messageID、partID（或经过验证的 callID）。不同服务器、会话之间不得串状态。会话删除或服务器移除时清理相关缓存。

顶层折叠控制的只是过程区。点击链接、复制按钮、详情中的文字选择，均不得触发父级折叠。禁止 button 内嵌套 button 或可交互链接。

## 5. 思考、正文和工具的呈现细则

### 5.1 思考

- 仅显示服务端实际提供的可展示 reasoning 内容，不推测或生成额外思考。
- 如当前数据没有独立标题字段，使用“思考”加第一行预览；CSS 单行省略。不要为模仿视频英文标题额外调用模型生成标题。
- 展开后显示一次完整 reasoning，正常换行；标题不再重复长预览，改成“思考”。收起恢复预览。
- 无内容时不显示空的可展开行；仍在等待时由运行状态提供反馈。
- 若正文很长，初版让它在主聊天滚动容器内展开；不要再加三级“查看全部”。

### 5.2 对用户的正文

- 进展正文和最终正文沿用现有 Markdown 渲染，段落、列表、代码、文件链接保持可用。
- 进展正文前不添加“进展”标签，不重复预览，不加灰底容器。
- 不通过正文包含“完成”“总结”等字词猜测最终回答；只能利用已有 message/run 分组、完成状态及经过验证的数据语义。
- 最终回答与中间正文的边界必须在数据层定义并测试。不能因为新 assistant message 到达就把已显示的文字大段搬动，导致阅读位置跳变。

### 5.3 工具摘要

| 工具 | 成功收起态示例 | 展开态标题 | 详情 |
| --- | --- | --- | --- |
| bash/shell | 已运行 git status --short … ✓ | 已运行命令 ✓ | 完整原始命令、输出、实际提供的退出码 |
| read | 已读取 README.md ✓ | 已读取 README.md ✓ | 实际返回的读取内容 |
| edit/write | 已编辑 README.md ✓ | 已编辑 README.md ✓ | 可用的改动或输入/输出；不伪造 diff |
| grep/glob | 已搜索 README … ✓ | 已搜索 ✓ | 搜索参数和结果 |
| question | 已提问 工作目录 … ✓ | 问题详情 ✓ | 已有问答数据；未答状态走已有可操作入口 |
| 未识别工具 | 工具名称 + 实际标题/目标 | 工具名称 | 通用输入/输出回退 |

动词必须与真实状态一致：pending“等待运行”，running“正在运行”，completed“已运行”，error“运行失败”；read/edit 等同理。成功勾选沿用用户此前明确要求，视频中未明显展示的这一差异属于主动保留。

收起态为透明背景，正文栏宽度内一行省略。完整命令保留原数据；折叠摘要可将换行转换为空格，但复制必须使用原文。默认不显示每条工具的毫秒耗时；详情中可保留。

展开态沿用简短标题，不能再次把完整长命令塞回标题。详情在当前行下方出现，轻微底色、细边框、圆角；Shell 标题与复制按钮独立。命令与输出分区，空输出明确显示“命令已完成，无输出”，请求失败显示“详情加载失败”与重试，加载中显示加载状态。三种情况不能统一当成“没有内容”。

长输出建议默认最大高度 20rem，面板内可滚动；提供“展开全部 / 收起输出”作为长日志的可选高度控制，不再隐藏整个工具输入。普通文本允许换行，表格/代码需要保留列对齐时只在自身横向滚动。所有内容必须可达，禁止只用 overflow-hidden 或渐隐遮住尾部。

文件名称若打开右侧文件栏，使用独立链接/按钮，不劫持整行折叠。多个文件的 diff 默认先显示文件列表，点击文件才展开该文件内容；“查看差异”继续使用已有右侧审查入口。

## 6. 视觉规格（建议起点，需实机校准）

录屏呈现近黑色背景、浅色正文、灰色状态和命令、蓝色文件链接。默认平面化，只有用户气泡、输入框及展开的工具面板有明显底色。AI 无头像、徽标、彩色左边线及发光进度条。

| 项目 | 初始实施值 |
| --- | --- |
| AI 正文 | 1rem，line-height 1.65，常规字重 |
| 过程/工具摘要 | 0.875rem，line-height 1.5，次级文本色 |
| 工具详情代码 | 0.8125rem，等宽字体，line-height 1.6 |
| 内容栏 | max-inline-size 52rem；在聊天主面板内居中；窄屏占可用宽度 |
| 左右留白 | clamp(1rem, 4%, 3rem)；计入容器 box-sizing |
| 段落间距 | 0.75rem；过程节点之间 0.5–0.75rem |
| 顶层耗时行 | 正文上方，下面一条 1px 低对比度分隔线 |
| 摘要点击区 | 最小高度 2rem；触控模式至少 2.75rem |
| 图标 | 1rem，线性图标；成功只加一个小勾选 |
| 详情面板 | 0.5rem 圆角、1px 边框、0.75rem 内边距 |
| hover / focus | 仅当前可点击行出现轻底色；键盘焦点明显 |
| 展开动效 | 120–160ms；尊重 prefers-reduced-motion |

使用现有主题语义变量，不全局硬编码视频颜色。浅色主题沿用同一层级。可先以深色背景约 #171717、面板约 #202020 作视觉比对，但最终使用 token，并检查次级文字可读性。

所有字号、间距、图标和宽度随现有界面缩放机制变化。当前源码根字号由 --ui-scale 控制，应使用 rem 等相对单位，不再次乘缩放因子，也不按视频物理像素设置字体。4K/Retina 视频像素不是 CSS 像素。

只在摘要使用 truncate。正文链路的 flex/grid 子项必须可收缩（min-width: 0、max-width: 100%）；普通段落使用 overflow-wrap: anywhere。不要在整条 assistant/run 容器上裁切横向溢出以掩盖布局错误。

推荐逻辑：run 内各 message 按已有顺序逐 part 生成展示项 → 同一工具调用更新原项 → 每项关联源 messageID/partID → 明确过程项与回答项。迟到 envelope 或部分事件缺失时沿用现有隔离逻辑，不把未知 parent 的内容错误合并到相邻用户回合。

## 8. 数据、异步与滚动约束

1. 先展示 store 已有内容。只有需要详情时才调用已有 createMessageService(...).get(sessionID, messageID, dir)，由正确服务器客户端和工作目录提供上下文。这是源码中已存在的请求路径，不要求添加端点。
2. 详情按 partID 优先匹配，callID 回退必须限定同一消息。并发展开合并重复请求；切换会话或卸载后忽略无效回包。
3. 旧 HTTP 回包不得盖过新 SSE 状态/输出。当前 loadedPart() ?? props.part 有持续使用旧快照的风险，实施时定义并测试最新状态优先、详情补缺的合并规则。
4. 不因为 output 缺失而虚构终端结果、思考标题、退出码或文件差异。没有详情和没有输出必须区分。
5. 运行状态与折叠状态分离。重试、完成、取消改变状态文案，不强制改变用户折叠选择；没有可靠耗时则显示“已完成”，不编造时间。
6. 用户正在底部跟随时新正文保持可见；用户向上阅读或点击展开时保持被操作行的位置，不强制滚到底。流式期间展开/收起不能被自动跟随逻辑覆盖。
7. 工具详情、Markdown 图片/代码等高度变化必须通知虚拟列表测量；保留旧消息分页锚点。不能为解决跳动关闭虚拟化或每个 token 重建整条列表。
8. 全部操作支持键盘 Enter/Space；折叠按钮有 aria-expanded 和 aria-controls；隐藏内容不可聚焦；计时更新不逐秒触发屏幕阅读器播报。

本次分析没有读取 docs 内 OpenAPI 文件，也没有声称核验服务端契约。实施优先沿用已存在的生成类型及 service；如确需新增 API 能力，作为独立工作核验，不在本 UI 改版中猜测字段。

## 9. Agent 分阶段任务

按以下顺序执行，每阶段先满足验收再推进；不要同时让多个 agent 修改同一个消息组件。

### A. 建立顺序与分类模型

范围：activity 推导与对应测试。目标：保留正文、工具、reasoning 的源顺序，区分最终回答，保留 run key 和操作消息 ID。

验收：输入“进展 A → 工具 A → 进展 B → 工具 B → 最终回答”，显示同序且每段一次；第二个用户回合与迟到消息不串组；普通回答无空过程区。增加回归测试，特别验证 assistant 消息追加时不丢文字、不重复搬动正文。

建议提交：refactor(messages): derive ordered reply items

### B. 实现平面回复及折叠状态

范围：ProcessFold、MessageBubble、activityViewState 及局部样式。依赖 A。

验收：使用本文默认状态表；移除本区域卡片时间线；思考一行、进展直显、回答始终可见。打开工具/思考后经历 delta、对象替换、虚拟化卸载仍保留状态；跨会话不串状态。

建议提交：feat(messages): render flat expandable reply activity

### C. 完善工具详情

范围：ToolPart、工具详情组件、i18n。依赖 B。

验收：收起长命令一行，展开标题变短，详情显示完整原文；成功勾选保留；错误、加载中、无输出分离；延迟回包不会覆盖实时输出；多工具可独立控制。多个 diff 文件不自动全部展开。

建议提交：feat(messages): refine inline tool disclosures

### D. 滚动及视觉验收

范围：必要的 MessageList 高度/锚点适配及 E2E。依赖 A–C。

## 10. 验收剧本与完成条件

| 场景 | 必须看到 / 验证的结果 |
| --- | --- |
| 普通一段回答 | 无 AI 图标、灰底外框或空统计条，文字自然排版 |
| 等待首个事件 | 只有轻量“正在思考”，不叠加多个忙碌进度条 |
| 混合回复 | 正文、思考摘要、工具按实际顺序穿插，不重复进展文本 |
| 多行长命令 | 收起一行省略；展开短标题 + 完整可复制命令及输出 |
| 20 个工具 | 全部默认只显示单行摘要；点击一个只展开一个 |
| 完成正在阅读的回复 | 计时停止，阅读位置及折叠选择不变 |
| 收起顶层 | 中间过程隐藏，最终回答、待用户处理入口仍可访问 |
| 工具 error / 空输出 / 网络失败 | 三者不同文案，失败能重试，不假装没有内容 |
| 流式与详情请求并发 | 不丢增量、不回退状态、不自动收起 |
| 历史分页 / 会话切换 / 虚拟化 | 顺序与展开状态符合第 4 节，不串会话 |
| 中文长段落、无空格路径、代码表格 | 正文不裁切；横向滚动仅发生在必要的代码/表格内 |
| 主聊天宽度 360 / 768 / 1200 CSS px | 无全页横向溢出，工具按钮仍可用 |
| 界面缩放 80% / 100% / 120% / 150% | 正文、摘要、图标同比变化，无二次缩放 |
| 深浅色、键盘、减少动效 | 对比度足够，焦点可见，所有折叠可键盘操作 |
| 文件链接 / 多文件 diff / 回退菜单 | 原有右栏行为和消息操作不回归 |
