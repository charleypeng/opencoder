# Desktop UI Improvement Plan

日期：2026-09-08。状态：待实施的设计计划，本文不表示功能已经实现。

## 1. 目标与边界

把 OpenCoder 优化为适合长时间工作的桌面客户端：鼠标容易发现操作，键盘能够连续完成任务，聊天、文件和审查之间切换不丢上下文。

优先保证可预测性、阅读稳定性和操作效率。沿用当前平面聊天风格、主题和信息层级；不要借交互优化重新设计时间线、卡片背景、阴影或字体。动效任务只改变用户主动操作时的过渡。移动端不作为本计划的设计基准，也不应被桌面调整误伤。

保持此前已明确的产品约束：会话列表不恢复日期；工具行保留动作摘要和成功勾选；多个 diff 默认先展示文件列表，点击文件名再展开；右栏支持自由调整至零宽度且可恢复；工作目录选择器仅由明确的用户操作打开。

本文基于仓库代码和本任务历史反馈，不是对当前桌面运行版本的全面实测。实施前应逐项复核；已满足的要求直接补验收证据，不重复开发。不得把尚未验证的建议当作已确认缺陷。

## 3. 操作规则

### 3.1 鼠标

- 高频操作提供可见入口；次要操作放更多菜单，右键菜单作为加速入口。不能要求用户必须猜到右键。
- 单击会话打开会话；工作区行选择工作区，独立箭头负责折叠。若现有行为不同，迁移前明确展示规则，避免一次点击同时触发多个动作。
- 文件树单击预览、双击保留标签仅在预览标签机制完整时引入；预览标签必须有视觉区分。拖选文字不能触发折叠、文件打开或发送。
- 紧凑图标按钮建议 28–32 CSS px 命中区，列表行建议 28–32 CSS px；图标本体 14–16 CSS px。使用现有 token 换算，避免强行套用移动端大按钮。
- 图标 hover 与键盘 focus 均显示名称；有快捷键时显示实际配置值。工具提示延迟建议 400 ms，不能遮挡下一步操作。
- 长标题默认省略；保留用户要求的走马灯设置，补充完整标题提示。鼠标离开即停止，减少动态效果模式只展示静态提示。

### 3.2 键盘与焦点

- Tab / Shift+Tab 按可理解的顺序移动焦点。把“Tab 切换 agent”改为显式可配置选项；新默认采用焦点导航，已有自定义配置保留并可恢复默认。
- 树和列表使用单一 Tab 入口及 roving focus：上下移动，左键折叠或到父项，右键展开或到首个子项，Home/End 到首尾。键盘焦点与已打开会话选择态分开显示。
- Enter 打开聚焦项；Space 切换折叠按钮；Shift+F10 打开上下文菜单。菜单用方向键导航，Escape 关闭并归还焦点。
- Escape 优先关闭当前弹层/菜单/搜索建议，其次退出局部模式。只有输入区的明确停止规则才可中止生成，避免关闭菜单时顺便终止任务。
- 对话框限制焦点在内部，关闭回到触发位置；切换会话保持用户明确选择的焦点区域，后台事件不能抢焦点。
- macOS 使用 Cmd，Windows/Linux 使用 Ctrl；保留明确配置的组合。终端聚焦时，复制、中断、Tab、方向键优先交给终端。
- 中文输入法确认、长按按键、输入建议选择不能触发误发送。发送偏好必须在输入框附近可发现。

### 3.3 快捷键发现与建议

复用现有注册表，不添加第二套全局监听。以下是产品动作规则；新增组合在实施时检查系统、终端、输入法和已有配置冲突。

| 动作           | 默认/建议                | 适用边界                                |
| -------------- | ------------------------ | --------------------------------------- |
| 命令面板       | 保留 Cmd/Ctrl+K          | 全局可用；展示当前上下文及不可用原因    |
| 新建会话       | 保留 Cmd/Ctrl+N          | 在当前工作区创建，随后聚焦输入框        |
| 打开文件       | 保留 Cmd/Ctrl+P          | 结果进入右栏；Escape 返回原焦点         |
| 工作区全文搜索 | 保留 Cmd/Ctrl+Shift+F    | 与聊天内搜索分开                        |
| 聊天内查找     | 建议 Cmd/Ctrl+F          | 仅聊天区域；终端/文件查看器保留局部语义 |
| 焦点区域轮换   | 建议 F6 / Shift+F6       | 侧栏、聊天、输入框、右栏；跳过隐藏区域  |
| 收起/恢复右栏  | 新增命令面板动作         | 组合暂不预设，设置中可绑定              |
| 重命名会话     | 菜单入口，建议 F2        | 列表焦点下生效，系统拦截时菜单可达      |
| 停止生成       | 明确的停止按钮及既有配置 | 菜单与输入法拥有更高事件优先级          |

## 4. 优先级与实施规格

### P0：阅读与操作稳定性

**DUI-01：会话首次打开和历史恢复。** 覆盖加载中、有消息、只有隐藏控制消息、历史分页、真正空会话、请求失败六种状态。加载失败给出重试；不能以空白代替加载或错误。恢复分页不要求发送消息，不应调用生成接口。保存阅读锚点时使用消息标识及相对偏移，适配虚拟列表测量变化。验收：重启后打开已压缩会话，不滚轮、不发消息即可看到可见历史；失败和重试路径可辨认。

**DUI-02：滚动、折叠和动效。** 用户离开底部后暂停跟随，提供“回到最新”入口；是否显示新消息数量应以可靠计数为前提。主动展开内容保持触发标题的视口位置，收起时触发按钮仍可见。动画只因手动开关触发，初次加载、计时器刷新、流式增量和虚拟列表重新挂载不得重播。建议 160–220 ms 非弹簧缓动；正文不缩放、不整体漂移；减少动态效果时立即切换。验收：嵌套展开、快速反向点击、长输出、生成中操作均无反复闪动，结束 500 ms 后静态内容位置稳定。测试应验证位置与状态，不能把某个 CSS 属性名称作为唯一质量标准。

**DUI-03：分栏和溢出。** 保持右栏自由调宽，边界为当前窗口可用空间；拖动阶段不对连续宽度变化施加 transition，释放后才保存尺寸。分隔线视觉细、命中区建议 6–8 px，hover/focus 可见；补双击恢复默认宽度。恢复按钮使用最近非零宽度，在较小窗口中夹紧到可用空间。若用户把聊天压得极窄，可保持聊天隐藏/工具最大化的明确状态，并提供返回入口；不强制抢回宽度。正文可换行，命令摘要省略，代码/表格/diff 仅局部横向滚动。验收：零宽恢复、键盘调宽、窗口缩小、100%/120%/150% 缩放下无不可达按钮、页面级横向溢出或永久遮挡。

### P1：减少鼠标距离与键盘中断

**DUI-04：工作区和会话导航。** 行尾更多入口在 hover/focus/菜单打开时显示并预留位置，避免标题跳动。工作区内新建入口就近放置；新建后的名称和输入焦点明确。现有标题大小与无日期规则保留。提供“复制会话链接/标识”和“复制工作目录”便利项，其中链接必须由真实接口/已有分享功能支持，不能编造。目录菜单明确区分“查看目录内容”“更换工作目录…”；后者才打开选择器。验收：纯键盘完成打开工作区、新会话、重命名、切换和展开；取消选择目录后不会自动再弹。

**DUI-05：聊天操作和输入。** 选中文本提供轻量复制/引用入口；引用进入草稿并可编辑。消息更多菜单在 focus 时可达；回退说明影响并把原文带回输入框。有草稿时不得无声覆盖，提供保留草稿或替换的明确选择。输入框支持粘贴图片/拖入附件并显示上传状态与失败重试；先盘点现有能力，只补缺口。模型/agent 选择器支持搜索、当前值和可读全名。验收：IME Enter 只确认候选；附件失败不丢正文；切换会话按会话保存草稿，返回仍能继续编辑。

**DUI-06：文件和 diff。** 所有打开文件动作进入同一右栏查看上下文，显示文件名、路径、返回/关闭入口；导航后可回到来源聊天。diff 显示明确范围“工作区”或“本次回复”，点击“查看差异”打开右栏相应范围。多文件默认展示折叠列表，按文件展开，记住各文件选择；提供下一处/上一处修改和复制路径。无数据时区分加载失败、内容尚未返回、确实无差异，不能统一显示“没有差异”。验收：两文件以上逐个展开；关闭右栏恢复原聊天位置；长路径不撑破布局。

**DUI-07：命令面板与焦点统一。** 每个可通过菜单执行的高频动作可被搜索，支持中英文名称及已有别名，显示有效快捷键。按区域确定动作可用性，例如没有活动会话时禁用回退。结果排序优先当前上下文，不改变用户已输入的查询。验收：纯键盘完成新会话、查找文件、打开设置和恢复面板；不抢占终端 Ctrl+C，不在弹窗关闭时误停止生成。

### P2：在基础交互稳定后增加便利性

- 会话固定到顶部、最近访问和待处理过滤。固定仅改变导航，不改变会话数据；持久化按服务器和工作区隔离。
- 聊天内搜索与上一个/下一个匹配。搜索范围必须显示“已加载历史”或“全部历史”；后者需核对 API 能力及分页成本，不假定后端支持全文搜索。
- 文件预览标签与保留标签、最近关闭恢复；先核对现有 viewer store。不得默认创建无限标签。
- 设置搜索、恢复某一布局区域、快捷键冲突提示。布局重置不能清除服务器、会话和草稿。
- 有待处理权限/问题时提供稳定的入口和数量；点击定位对应会话。通知不抢焦点，用户已处理的请求及时消失。

不纳入近期：全新配色、装饰时间线、批量删除、复杂弹簧动画、拖动重排全部界面、多窗口重构。它们不能直接解决当前高频摩擦。

## 6. 验证与发布顺序

先完成 P0 并演示稳定性，再完成 P1 高频路径，最后根据实际操作反馈选择 P2。各阶段以可验证结果作为出口，不把所有建议一次性堆进一个改版。

测试矩阵至少覆盖 macOS WebKit 与 Windows Chromium/WebView2；无法运行的系统明确标为未验证。使用逻辑窗口尺寸 1280×800、1440×900、2560×1440，各测 100%、120%、150% 界面缩放；4K 物理像素不能直接当作布局宽度。再覆盖左右栏关闭、右栏极窄/极宽、浅色/深色和减少动态效果。

验收路径：打开已有历史会话 → 读旧消息 → 生成过程中向上滚动 → 手动展开工具 → 复制输出 → 打开单文件 diff → 收起并恢复右栏 → 返回草稿 → 中文输入确认 → 主动发送。全程无自动选目录、无抢焦点、无内容遗失和持续抖动。另用纯键盘完整执行一次导航路径。

性能观察：拖动时面板跟随指针，空闲且未主动操作时不产生折叠动画；长会话展开后位置收敛，无持续重排循环。记录测试机器、数据规模、帧时间或浏览器性能记录，未测量时不要宣称“60 FPS”。

每张实施卡按仓库要求执行 `pnpm verify`；聊天/会话/渲染改动还须执行 E2E。失败必须报告具体用例与复现条件；没有基线复现证据不得宣称是既有问题。自动化通过不能替代手动动效验收。

效果评估使用本地测试记录，不增加遥测服务或付费依赖：比较“找到并展开指定工具”“恢复右栏”“切换后继续草稿”的点击次数、完成时间和误操作数。第一轮先记录现状，再比较改进版；优先减少一次往返或一次焦点中断，而不是增加更多入口。
