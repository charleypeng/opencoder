## 附录：PTY 协议联调记录（TASK-M6-01 填写）

> **本记录为 contract-based 验证**：环境无真实 `opencode serve`，以下结论全部
> 基于 `docs/openapi_v1.18.11.json` 契约分析（标注「契约」），**待真实服务端
> 联调确认后更新**。未执行真实服务端建连回显（验收项 SKIP，原因如上）。

- 端点：`GET /pty/{ptyID}/connect`
- 协议（契约记录）：
  - **文档形态**：OpenAPI 将该端点文档化为普通 HTTP —— 200 返回
    `application/json` boolean（"Connected session"），可选 query：
    `directory`、`workspace`、`cursor`、`ticket`；错误：403 Forbidden、
    404 NotFound。**契约未记录 WebSocket 子协议与消息帧格式**（契约分析
    结论：真实服务端为 WS 升级端点，子协议/帧语义需真实联调确认）。
  - **认证方式**（契约）：先 `POST /pty/{ptyID}/connect-token` 换取
    `PtyTicketConnectToken { ticket, expires_in }`，ticket 作为 connect 的
    query 参数。注意字段名为 **`ticket` 而非 `token`**（TASK 原文的
    `?token=` 假设与契约不符，实现以契约为准）。
  - **帧格式**（契约推断）：WS 二进制帧承载终端数据（客户端键盘输入 → 服务端，
    服务端 → 终端输出/回放）；`cursor` query 疑似滚动缓冲续接游标。子协议名
    与帧边界语义待真实服务端确认。
  - **resize 通道**（契约）：resize 走 REST `PUT /pty/{ptyID}`（body
    `{ size: { rows, cols } }`），**不经过 WebSocket**。
  - **实现选择**（基于契约）：建连流程 = connect-token(REST) → 组装
    `ws(s)://{base}/pty/{ptyID}/connect?ticket=…&directory=…` → Rust 侧
    tokio-tungstenite 建连（WS 路径下沉 Rust，规避 WebView 直连的
    CORS/ATS 问题，见 `src-tauri/src/transport/ws.rs`）。
  - **通道载荷**（实现记录）：tauri 2.11.5 `Channel::send` 仅支持 serde
    序列化（无原始字节 `send_raw`），二进制帧以 `{ "bytes": [...] }` JSON
    包裹推送（mock/dev 可接受的 ~4x 膨胀），连接终止以
    `{ "type": "pty.ws.closed" }` 控制帧通知前端；重建/断线重连**不实现**
    （PTY 随 WS 断开而死亡，读循环错误即关闭）。
- 联调环境：（待填写：服务端版本 / 日期）— 无真实服务端
- 结论与偏差：
  1. 与 TASK 原文的偏差：connect URL 参数为 `ticket`（契约
     `PtyTicketConnectToken` + connect query 确认）而非 `token`。
  2. `GET /pty/{id}/connect` 契约文档为 JSON boolean，真实协议（WS 子协议、
     帧格式）以服务端实现为准 —— 待联调后更新本附录。
  3. resize 走 REST PUT 而非 WS 帧（契约确认）。
  4. mock 模拟：express 无法原生 WS 升级，`/pty/{id}/connect` 返回
     426 Upgrade Required + JSON 说明（含契约描述与 ws 提示）；WS 数据通道
     由独立 `tests/mock-server/ws-echo.mjs`（`ws` 包）模拟，L3 契约测试
     走「spawn ws-echo → 连接 → 发送字节 → 回显断言」链路。
  5. 验收「真实服务端建连回显」：**SKIP**（无真实服务端），以契约分析 +
     mock WS 验证替代；待有真实环境后按本附录协议步骤复测并回填。
