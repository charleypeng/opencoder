## TASK-M8-08 落地备注

- **模块**：`src/features/pet/petState.ts`（纯状态机）+ `tokenRate.ts`（token 速率 store）+ `petEvents.ts`（watcher）+ `PetShell.tsx`（CSS 动画宠物 + 交互）；Rust 侧仅两处小改——`pet_set_intensity` 命令 + `pet-intensity` 事件（强度通道），`pet_set_size` clamp 下限降至 48（收展）；接线点——`stores/events.ts`（message.part.delta → bumpTokenRate）、`DesktopShell.tsx`（按活动服务器挂载 watcher）。
- **状态机**（`petState.ts`，ui-design §6）：`PetState` = idle/working/waiting_permission/success/error/attention；纯 reducer `reducePetState(current, event, ctx)`——事件 = `session.status`（busy/retry/idle/error）+ `permission.asked/replied` + `question.asked` + `interaction` + `transient.expired`；**显示优先级 error > waiting_permission > working > success > attention > idle** 决定并发事实谁渲染；**每次 fold 全量重述事实**（聚合会话状态 + 权限/问题队列），因此单事件无需幂等；释放事件（session.status 重述、permission.replied、transient.expired）强制其目标（fold 已重推底层事实）；`waiting_permission` 经 `toAnimationState` 映射为 pet 窗口动画态 `waiting`（与 M8-07 序列化契约逐字对齐）；success 3s / attention 5s 瞬态由 watcher 的定时器处理（离开瞬态即清定时器——新生成打断旧 success 定时器不误回退）。
- **事件联动**（`petEvents.ts`）：`startPetWatcher(serverId)` 在 createRoot 下三个 effect——(1) 会话状态 + 权限队列 + 问题队列聚合 fold 后**单次** `setPetState`（fold 顺序：权限/问题事实在前、会话事实在后——队列排空时释放等待后由会话重述落到正确基态；**中间态永不送达 pet 窗口，无闪烁**）；(2) tokenRate → `workingIntensity`（0-100，25 增量/秒饱和）→ `setPetIntensity`（值不变不重发，不刷 IPC）；(3) dispose 守卫（Solid 调度器在 root 释放后可能仍 flush 一次队列中的 effect——守卫拦截，杜绝旧服务器状态外发）。**挂载快照即应用**（宠物反映当前真相——区别于 haptics/notifications watcher 的「首次观察不触发」）。
- **token 速率**（`tokenRate.ts`）：`message.part.delta` 经 events.ts 路由 `bumpTokenRate()`（滑动 1s 窗口，惰性启动的 250ms 剪枝定时器自动衰减——爆发结束后强度自然回落）。
- **PetShell 动画**（TASK-M8-08 的渲染器决策）：**无 .riv 资产——以纯 CSS 宠物落地**（blob + 双眼，状态键帧：idle 轻浮、working 打字抖动（动画时长由强度内联驱动 950ms→400ms）、waiting 举手挥手（paw）、success 弹跳 + 眯眯眼、error 垂头 + 眼睛下垂、attention 弹跳 + 星闪（转发）/ 心跳（摸头））；prefers-reduced-motion 全部归零为静态宠物（状态特征保留）；资源 < 500KB 天然满足（零资产）；**Rive 接入点已就绪**——`PetRenderer` 接口（setState/setIntensity）+ 状态枚举即其契约，资产到位后 Rive 实现可插拔替换，状态机与事件联动零改动。
- **交互**（PetShell 本地）：单击 = 摸头（弹跳 + 心形，attention 5s 后回落到最后转发的状态；**转发状态随时压过本地摸头**——无跨窗口通道；**刻意不 invoke pet_set_state**：主窗口 watcher 独占转发，自回声会污染回退锚点——与任务建议的偏差，记录于此）；双击 = 收展（收起到 48×48——Rust `pet_set_size` clamp 下限放宽，见上——tiny blob + 恢复图标 + 隐藏 pill/齿轮/设置弹层，双击还原到存储尺寸）；单击带 220ms 防双击抖动（双击的首击不会误触发摸头）。
- **Rust 侧**：`pet_set_intensity(intensity: u32)`（clamp 0-100，记忆 `last_intensity`，`pet_show` 时随 `last_state` 一并重发——新窗口起步即同步）；`clamp_pet_size` 范围改为 [48, 200]（`COLLAPSED_PET_SIZE`——设置滑杆下限仍 120，纯前端常量）；mute 仍为纯存值（CSS 宠物无声，标志留给未来音效渲染器）。
- **测试**：L1——reducer 全矩阵（优先级矩阵、success/attention 瞬态与到期、错误解除/权限排空/完成三条释放路径、waiting 映射、ctx 无关性）、tokenRate（窗口滑动/自动衰减/重置、intensity 映射含垃圾输入）、watcher（挂载快照、完整编码流 working→success→idle、错误与解除、权限期间等待与排空落基态、question→attention 5s 回退、新生成打断瞬态、强度转发不重发、dispose 停止）、门面（setPetIntensity 参数/守卫/事件校验/unlisten）、events 路由（delta 计数、非 delta 不计数）；L2——PetShell（blob 状态类、强度驱动动画时长、摸头回退、转发压过摸头、转发 attention 星闪、双击收展与还原、收起时点击/右键惰性）、DesktopShell（watcher 按活动服务器挂载 + 切服重建 dispose 旧 watcher）；Rust 单元（collapse 尺寸 clamp、强度 clamp）。
- **验收对应**：编码全流程（busy→working、idle→success 3s→idle、权限→waiting、错误→error、问题→attention）状态流转自然（fold 单发无闪烁）；彩蛋可触发（单击摸头 + 心形）；双击收展。
- **L4 备注**：真实拖拽区内点击/双击行为（Tauri drag region 对 blob 指针事件的分派）属壳级 E2E，随 M10 L4 基建验证；Rive 资产接入待定（CSS 宠物为当前渲染器）。
- **偏差**：①摸头为 pet 窗口本地行为，不 invoke `pet_set_state`（自回声污染回退锚点——任务建议的「为一致性而 invoke」被放弃，转发状态即一致性来源）；②强度经独立 `pet-intensity` 事件通道（不改 `pet-state` 载荷，M8-07 契约与既有测试零改动）；③`pet_set_size` clamp 下限 120→48（收展需要；设置滑杆范围不变）；④mute 标志按计划以 no-op 消费（CSS 宠物无声）。

## TASK-M8-06 落地备注

- **插件与平台事实（spike 结论）**：`tauri-plugin-notification` 2.3.3（crates.io + npm `@tauri-apps/plugin-notification`，与 haptics/barcode-scanner 同为 plugins-workspace）。桌面实现 = notify-rust——macOS 走已废弃的 `NSUserNotificationCenter`（**无需授权弹窗**；桌面端 `request_permission`/`permission_state` 无条件返回 Granted，guest-js init 会把 `window.Notification.permission` 置为 granted），Windows toast、Linux libnotify；guest-js 的 `sendNotification` 实际是 `new window.Notification(...)`（init 脚本把构造器 patch 成 `plugin:notification|notify` invoke）。**Click API 结论：桌面无点击事件**——`onAction`（`actionPerformed`）仅由 iOS/Android 原生端发出，notify-rust 的 `show()` 不注册任何点击回调，因此桌面端「点击通知聚焦窗口」**无法用 2.3.3 实现**，记录为限制（Backlog：fork 插件或自研 Rust 通知模块接 notify-rust Action::callback）。移动端复用同一封装（M7）：`subscribeToNotificationClick` → `focusWindow()`（权限/问题 Sheet 是全局的，窗口前台后自动弹出，无需导航）。另：`Options` **无 tag 字段**（2.3.3 的 NotificationData 无 tag），门面 `tag?` 参数仅为 API 对齐而接受、实际忽略。
- **模块**：`src/services/notifications.ts`（门面）+ `src/stores/notifications.ts`（偏好）+ `src/services/notificationEvents.ts`（事件接线）+ `src/features/settings/NotificationsSection.tsx`（设置 UI）+ DesktopShell 接线；Rust 侧仅 `.plugin(tauri_plugin_notification::init())` + capability（`notification:default`；`core:window:allow-set-focus` 补入——`allow-is-focused` 已在 `core:window:default` 内，无需额外授予）。
- **门面**（`notifications.ts`）：`notify({ title, body, tag? })` 沿用 events.ts 的 outside-Tauri no-op 守卫；**权限首次使用才请求**（模块级 promise 缓存——桌面解析 granted 不弹窗；移动端拒绝后保持拒绝直到用户在系统设置重新开启，符合插件语义）；`isWindowFocused()`（`getCurrentWindow().isFocused()`，非 Tauri 恒 true——web 构建没有「后台」可通知）；`focusWindow()`（`setFocus`）；`subscribeToNotificationClick(onClick)`（onAction → `PluginListener.unregister()` 生命周期，非 Tauri no-op）。
- **偏好**（`stores/notifications.ts`）：`{ enabled?, perServer?: Record<serverId, bool> }` 持久化于 localStorage `oc-notifications`（沿用 desktopPrefs 纪律：畸形载荷丢弃、字段形状校验、storage 失败吞掉）；**缺字段 = 开启**（默认全开，设置 UI 只写显式值）；`notificationsEnabled` / `serverNotificationsEnabled` / `setNotificationsEnabled` / `setServerNotificationsEnabled` 纯函数。
- **设置 UI**：SettingsPage 新增 **Notifications 分区**（providers/shortcuts/desktop/notifications 四级 fallback 导航）——`NotificationsSection.tsx` 渲染总开关 + 每服务器开关（服务器列表经 `listServers()` 一次性拉取，失败只保留总开关；本地 Switch 组件命名避开 solid-js 的 `Switch` 导出——JSX 解析冲突实测）；开关即改即存，本地存储失败由 store 吞掉，故无内联错误 UI（区别于 Rust-backed 的 DesktopSection）。
- **事件接线**（`notificationEvents.ts`）：三个纯映射——`generationCompleted`（busy/retry→idle = 完成；首次观察不触发）、`queueGainedItem`（队列出现新 id；首次观察不触发）、`shouldNotify(focused, enabled, serverEnabled)`（**仅窗口未聚焦** + 总开关 + 服务器开关，三者与——聚焦时界面就在眼前，通知属噪音）；`startNotifications(serverId)` 按 hapticEvents 同一纪律（createRoot + 基线同步快照 + 删除会话基线修剪防复用 id 误报），三个 createEffect 分别盯会话状态/权限队列/问题队列，命中后**按触发时刻**读取偏好 + 窗口聚焦做门禁再 `notify`——生成完成通知 body 为会话标题（title→slug→id 回退链），权限/问题通知 body 为**所属会话**的标题（取新入队请求的 sessionID）。
