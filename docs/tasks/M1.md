### TASK-M1-01 Rust REST 传输通道（ADR-002）
- **前置**：M0-03 ｜ **模块**：`src-tauri/src/transport/`、`src/services/`
- **范围**：`src-tauri/src/transport/http.rs`、`src-tauri/src/commands.rs`、`src/services/client.ts`、`src/services/errors.ts`
- **API**：全部（传输基座）
- **规格**：
  - Rust：`http_request` command —— reqwest（rustls）发请求；入参 `{ serverID | url, method, path, query, body, auth, timeoutMs, requestID }`；Basic Auth 头在 Rust 侧注入（不写日志）；取消 token（切服务器/会话时 abort 在途请求）；错误分类序列化为 `ApiError { status, code, message, retriable }`
  - TS：`ApiClient` 门面 —— 保持 `client.GET/POST(path, …)` 类型安全外观（openapi-typescript）；transport 抽象双实现：生产 = `invoke("http_request")`，dev-only = fetch（`VITE_TRANSPORT=fetch`，仅供 Playwright/纯浏览器开发，此时 mock 需 `--cors`）；`?directory=` 全局注入点；调用方零感知
- **验收**：经 invoke 对 mock server 发 GET/POST 成功；401/500/超时/断网错误分类正确；**无 CORS 依赖**（WebView 零直连，dev 环境 mock 不开 cors 也通）
- **测试**：cargo test（请求组装/错误矩阵/取消）+ L1（TS 门面 invoke 参数组装）+ L3 契约（请求构造）
- **提交**：`feat(transport): Rust REST 传输通道与 TS 门面 (TASK-M1-01)`

### TASK-M1-02 Rust SSE 管理器与 Channel 推送（ADR-002）
- **前置**：M1-01 ｜ **模块**：`src-tauri/src/transport/`、`src/services/`
- **范围**：`src-tauri/src/transport/sse.rs`、`src/services/sse.ts`
- **API**：`GET /event`、`GET /global/event`
- **规格**：
  - Rust：`sse_subscribe(server_id, directory?, channel) -> subscription_id` / `sse_unsubscribe(id)`；每订阅一个 tokio task，reqwest 流式读取 `text/event-stream` 逐行解析（处理跨 chunk 断行）；**事件过滤**（丢弃 `tui.*`/`workspace.*`）；**16ms 批刷**（帧内 delta 合并为数组一次 Channel 推送）；大 payload 原样透传字符串（TS lazy-parse）；指数退避重连（1s→30s 封顶）；60s 心跳判死；重连成功后推送 `server.connected` 且带 `reconnected: true`
  - TS：订阅门面 `sseSubscribe(serverID, directory, onEvent)`（创建 `Channel` + invoke）；事件分发到 store 的路由不变
- **验收**：mock 场景 sse-drop 下自动重连且事件不重复不丢失；高频 delta 场景 IPC 推送频率 ≤ 60/s（实测记录）；WebView 不可见时 Rust 侧流不中断
- **测试**：cargo test（断行/乱序/批刷窗口/重连时序，tokio-test）+ L1（TS 门面 Channel 事件注入 mock）
- **提交**：`feat(transport): Rust SSE 管理器与 Channel 批刷推送 (TASK-M1-02)`
