## 附录：TASK-M9-05 落地记录

**契约核实（1.18.11 openapi）**：
- `Config` schema 为 36 个顶层键的扁平对象、`additionalProperties: false`——**无 `theme` 键**（主题为客户端偏好，TASK-M9-03 的 oc-theme 体系；服务端会拒绝未知键）。表单字段按契约实现：`model`、`default_agent`、`share`（manual/auto/disabled）、`autoupdate`（true/false/"notify"）、`permission`（ask/allow/deny 或按工具规则对象）。
- PATCH 语义：`PATCH /config` 与 `PATCH /global/config` 的 body 即 Config schema 本体，服务端按**深合并**处理（嵌套纯对象递归合并、数组/标量整体替换、未出现的键保持不变），响应为**完整更新后的 Config**。
- `POST /instance/dispose`：200 返回纯 boolean；`directory`/`workspace` query 可选。`POST /global/dispose`（释放全部实例，200 返回纯 boolean，operationId `global.dispose`）**同样在 1.18.11 契约内**（openapi `/global/dispose`）——本任务只实现 instance 级 UI 入口，全局释放仅由服务封装（`disposeGlobal`）+ mock 路由，UI 入口留待后续；api-coverage §5 的列表已正确收录两端点。

**实现要点**：
- `src/services/config.ts`：`createConfigService(client)` — `get(dir?)` / `update(patch, dir?)` / `getGlobal()` / `updateGlobal(patch)` / `dispose(dir?)` / `disposeGlobal()`；patch 类型为递归 Partial（ConfigPatch）。
- `src/features/settings/config/ConfigSection.tsx`：Project/Global 作用域 tab；表单字段（model 用 provider+model 双下拉、default_agent 用 /agent 目录、share/autoupdate/permission 枚举下拉——permission 为对象时隐藏下拉改提示）；dirty 跟踪 → Save（PATCH 合并）→ 成功刷新基线 + toast、失败内联回滚；高级 JSON 编辑器（只读视图 ↔ 编辑态，实时解析校验 + 未知顶层键提示、合并补丁语义提示、失败回滚）；危险区 Dispose instance（确认面板说明服务端将被关闭、连接断开 → `POST /instance/dispose` → toast；确认面板为 GeneralSection 两步确认同款内联形态）。
- Model 写入格式：`providerID/modelID`（服务端可解析的限定形式；读取时兼容裸 id 与限定 id）。模型双下拉为**表单驱动**（有选择后即读 form，provider 切换立即换模型列表、model onChange 写入 form 的 provider，杜绝跨 provider 错配保存）；保存进行中切换作用域会丢弃过期的 PATCH 响应（避免旧作用域覆盖新作用域基线）；dirty 表单下切换作用域需确认（「放弃未保存的更改？」对话框，JSON 保存路径按基线语义操作）。
- Mock server：`/config`、`/global/config` 动态路由（按目录隔离的项目级状态 + 深合并 PATCH，非对象 body → 400）、`POST /instance/dispose` 与 `POST /global/dispose` → true；fixtures `config.json` / `global.config.json`；self-test 新增 7 条断言（形状、标量+嵌套合并、非对象 400、目录隔离、全局往返、instance dispose、global dispose）。
- 已知取舍：JSON 编辑器无法删除键（PATCH 合并语义下省略键 = 保持原值；如需删除需直接编辑服务端配置文件）；dispose 连接的实例会使 SSE 连接断开、应用退回服务器列表（本分区不做重连）；主题字段按契约不可写入（客户端 oc-theme 体系）。

**测试**：L1（config 服务载荷组装含目录透传、ApiError 透传；L3 块对活 mock 验证 get/update 合并/全局/dispose）、L2（分区：作用域切换、表单字段回填、dirty/save/失败保留、模型限定写入、permission 对象提示、JSON 编辑器校验/未知键提示/保存/失败回滚/取消、dispose 确认/取消/失败内联、加载失败 + 重试；SettingsPage 导航注册）、L3（self-test 7 条 config 断言）。

## 附录：TASK-M9-06 落地记录

**契约核实（1.18.11 openapi）**：
- `GET /mcp` 返回 `Record<string, MCPStatus>`；MCPStatus 为五态联合：`connected` / `failed+error` / `disabled` / `needs_auth` / `needs_client_registration+error`——**无 tools 字段**，客户端无法渲染工具数（规格中的「工具数」不可得）；`mcp.tools.changed` 事件（`EventMcpToolsChanged`）仅携带 `server` 名 → 客户端据事件刷新列表。
- `POST /mcp` body 为 `{ name, config }`，config 为联合：`McpLocalConfig`（`type:"local"`、`command: string[]`（可执行+参数数组）、`cwd?/environment?/enabled?/timeout?`）或 `McpRemoteConfig`（`type:"remote"`、`url`、`headers?/oauth?/enabled?/timeout?`）。
- `POST /mcp/{name}/connect` / `disconnect`：200 返回纯 boolean；未知服务器 → 404 `McpServerNotFoundError`。
- OAuth 三件套：`POST /mcp/{name}/auth` → `{ authorizationUrl, oauthState }`（无 provider 版的 `method/instructions` 字段）；`POST /mcp/{name}/auth/authenticate` → MCPStatus（描述为「启动流程并等待回调」，无请求体）；`POST /mcp/{name}/auth/callback` body `{ code }` → MCPStatus；`DELETE /mcp/{name}/auth` → `{ success: true }`。不支持 OAuth 的服务器 → 400 `McpUnsupportedOAuthError`。
- **无 `DELETE /mcp/{name}`**（1.18.11 契约确认不存在）→ 不做删除按钮（规格未列）。

**实现要点**：
- `src/services/mcp.ts`：`createMcpService(client)` — `list` / `add` / `connect` / `disconnect` / `authStart` / `authRemove` / `authCallback` / `authAuthenticate` / `authPoll`；自动流轮询沿用 M5-07 模式（`pollUntil`，2s×60s），因 authenticate 无请求体，`poll` 以 **query 扩展**传递（provider 版是 body `poll: true`），mock 端点为非阻塞实现、访问授权页后持久化 connected。
- `src/stores/mcp.ts`：`mcp.tools.changed` 事件的版本计数器（按服务器），事件路由器 `applyEvent` 新增该 case（`server` 名 → bump），`server.connected` 重同步时 reset；McpSection 的 `createEffect(on(serverId+version))` 即挂载加载 + 事件刷新（Solid 的 `on()` 默认 `defer:false` 首次运行即回调，因此无需额外 onMount——曾有双加载 bug，已用该语义收敛）。
- `src/features/settings/mcp/McpSection.tsx`：五态状态卡片（connected 绿/disabled 灰/failed 红/needs_auth 黄/needs_client_registration 红 + 错误详情可展开）、connect/disconnect（全局 busy 锁，失败内联保留旧状态）、添加对话框（本地：命令行拆 `command: string[]` + 环境变量行；远程：url + 请求头行；空键行丢弃；POST 响应直接应用不额外刷新）、needs_auth → `McpOAuthDialog`（镜像 ProviderOAuth：auth start → openUrl → 自动轮询/粘贴码 callback 双路径，取消中止轮询）；`mcp.tools.changed` → 列表刷新。
- Mock：`GET/POST /mcp` + connect/disconnect + auth 三件套 + 授权页 `GET /mcp/oauth/authorize?state=`（模拟 IdP 往返，扩展）动态路由；fixture `mcp.status.json`（connected / failed+error / disabled / needs_auth 四台）；状态流转：add → disabled、connect → connected（heal failed）、disconnect → disabled、OAuth 完成 → connected；self-test 新增 10 组断言（列表形状、local/remote 添加、400 校验、连接状态流转、404、自动流往返、码流、不支持 400、auth 移除）。
- 已知取舍：Mock MCP 状态为全局单份（未按目录隔离，config 已示范该模式但 MCP 验收聚焦状态流转）；`needs_client_registration` 无专属动作（按 failed 样式渲染 + Connect 重试）；authenticate 无 `poll` query 时 mock 同样非阻塞返回当前状态（真实服务端为阻塞语义，契约级验证记录同 M6 附录）。

**测试**：L1（mcp 服务载荷组装含目录透传、local/remote add body、OAuth 端点、`poll` query、ApiError 透传；L3 块对活 mock 验证列表/添加/连接流转/自动流/码流/400/404/auth 移除）、L2（McpSection：五态卡片 + 错误展开、connect/disconnect 刷新 + 全局锁 + 失败内联、添加对话框 local/remote 载荷与校验与行增删、OAuth 对话框自动流/码流/取消/启动失败、`mcp.tools.changed` 刷新、加载失败 + 重试、空态；纯函数 commandArray/rowsToRecord；事件路由新 case；SettingsPage 导航注册）、L3（self-test 10 组 MCP 断言）。

## 附录：TASK-M9-07 落地记录

**契约核实（1.18.11 openapi）**：
- `GET /lsp` → `LSPStatus[]`（`{ id, name, root, status: "connected"|"error" }`）；`GET /formatter` → `FormatterStatus[]`（`{ name, extensions: string[], enabled }`）。两者均带可选 `directory`/`workspace` query。
- `EventLspUpdated` 的 `properties` 为**空对象**（`properties: { type: object, properties: {} }`）——事件不携带任何数据，客户端只能 bump 版本后重拉 `GET /lsp` 获得新状态。
- `POST /log` body 为 `{ service, level: "debug"|"info"|"error"|"warn", message, extra? }`（service/level/message 必填，extra 为对象）；200 返回纯 boolean；400 为 `InvalidRequestError`。**单条一次请求**（无数组批量语义）。
- `GET /api/permission/saved`（V2）→ `{ data: PermissionSavedInfo[] }`，每条 `{ id, projectID, action, resource }`（均必填 string）；query 可选 `projectID`。`DELETE /api/permission/saved/{id}` → **204 无 body**（契约无 404 变体）。
- `POST /global/upgrade` body `{ target? }` → `{ success: true, version }` 或 `{ success: false, error }`。**按规格仅展示**：诊断页无按钮，只显示服务端版本 + 过旧提示（M8-09 的 `installation.update-available` 横幅机制）；Mock 注册该端点仅作契约覆盖（self-test 断言形状），客户端无调用方。
- **tokens/费用数据源决策**：Session schema 自带服务端计算的 `tokens`（`input`/`output`/`reasoning`/`cache{read,write}`）与 `cost: number` 字段，`session.updated` 事件已在 M2 路由进 session store —— 状态栏芯片直接读**当前会话**（`activeSessionId`）的这两个字段，展示取 input+output+reasoning（cache 不计入使用量）、cost 原样格式化为 `$X.XX`；不做客户端字符估算，也不从 step-finish part 累加（那是按步骤的、可能漏计的部分视图）。会话无 tokens 或两值均为 0 时隐藏芯片。

**实现要点**：
- `src/services/lsp.ts`：`createLspService(client)` — `status(dir?)` / `formatters(dir?)`；`src/services/log.ts`：`createLogService(client)` — `write(entry, dir?)`（`LogEntry` 类型取自 operation `app.log` 的 requestBody）；`src/services/permission.ts` 扩展 `savedList()` / `savedRemove(id)`（DELETE 路径为 `as ApiPath` 动态拼接）。
- `src/stores/lsp.ts`：按服务器 `{ lsp, formatters, version, loaded, formattersLoaded }`；`applyLsp`/`applyFormatters` 整体替换列表、`bumpLspVersion` 只加版本（事件空载荷）、`resetServer` 清桶（上下文重建后芯片重拉）。events 路由新增 `lsp.updated` case → bump；`server.connected` 重置清单补 `lsp`。
- 状态栏芯片（DesktopShell 底部）：`StatusBarLsp`（挂载 + 版本变化重拉 GET /lsp，显示 connected 计数，加载失败下版本回退以便下次事件重试）、`StatusBarFormatter`（挂载拉一次 GET /formatter，仅显示 enabled 名）、`StatusBarUsage`（`ml-auto` 靠右，读 session store 当前会话 tokens/cost）。格式化纯函数放 `src/shells/desktop/statusBar.ts`。
- 诊断分区 `src/features/settings/diagnostics/`：`logCapture.ts`（200 条环形缓冲 + 订阅者通知；`installLogCapture()` 幂等安装 window.onerror + console.error/warn 包裹，`[stores]`/`[diagnostics]` 前缀过滤，uninstall 还原原始钩子）；`logForward.ts`（`oc-diagnostics` localStorage 偏好 `forwardLogs`；订阅捕获 → 队列 → 触发点：20 条批量 / 30s 间隔 / 停止排空；批内 (level,message) 去重；逐条 POST /log，失败静默丢弃整批）；`DiagnosticsSection.tsx`（日志控制台 + 级别筛选 + 清空；回传开关；服务端版本 + 过旧提示；已保存规则列表 + 两步确认删除）。
- DesktopShell 挂载时 `installLogCapture()`（应用级捕获，非仅分区打开时）+ 偏好开启时 `startLogForwarding()`，卸载时双清理。
