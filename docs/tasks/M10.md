
覆盖率门禁在 `vitest.config.ts` 中只约束 `src/services/**` 与 `src/stores/**`（
docs/testing.md §3 L1 门槛），通过 `pnpm test:coverage` 独立执行；`pnpm verify`
不跑覆盖率（保持 CI 快），e2e.yml 亦不跑单测——职责分离，均记录于此。

### 基础设施决策（M10 记录）

1. **Tauri IPC shim**：浏览器（vite dev + `VITE_TRANSPORT=fetch`）没有 invoke/
   Channel/事件桥，`tests/e2e/tauri-shim.js` 以 `addInitScript` 注入
   `window.__TAURI_INTERNALS__`，实现服务注册表（内存）、健康监控（1.5s 轮询
   /global/health）、SSE（EventSource→Channel）、PTY 通道（客户端回显）与
   `plugin:event|listen`。测试通过 `window.__TAURI_SHIM__` 读遥测。
2. **E03 发消息与流式渲染分离**：mock 的 `prompt_async` 答 204 且不触发 SSE；
   UI 订阅 `/event` 默认重放 happy-chat。旅程 = 乐观气泡 + 204 往返（发），
   + 场景重放渲染 text/tool（流式），中途释放被 hold 的流以控制时序。
3. **场景选择**：UI 不携带 `?scenario=`，旅程用 `page.route` 改写 /event URL
   选择 permission-flow / question-flow / sse-drop；`holdEventStream` 按住首个
   /event 请求直到旅程就绪再放行（timeline 从放行时刻起播）。
4. **`?syncDelay=`（mock 扩展，docs/api-coverage.md §5）**：`server.connected`
   会触发客户端全量 re-sync，其快照替换会清掉 sync 期间到达的 t=0 事件（
   happy-chat 的 `session.created` 与 re-sync 竞争，E2E 首跑暴露）。shim 在
   SSE URL 追加 `syncDelay=250`，让场景在 re-sync 落定后开播。
5. **E12 断网→重连**：`scenario=sse-drop` 播放 3 个事件后断流；EventSource
   自动重连，mock 按连接重放场景 → 再次 `server.connected` → 重置 + re-sync
   （状态自动对齐）。健康腿用 Playwright route 掐断 /global/health → 状态点
   变红 → 恢复 → 变绿；`session.created` 在重连后仍对齐。
6. **tauri-driver 壳级用例（WebdriverIO）**：环境无 tauri-driver（本机未安装
   WebDriver 基础设施，桌面壳级验证归 M10-02/03 的打包首启走查），记为
   文档级条目而非 CI 步骤；e2e.yml 只跑 Playwright 12 旅程。
7. **app bug（E2E 首跑发现并修复）**：`stores/events.ts` 的 `server.connected`
   处理器原会重置 project store 桶，DesktopShell 的按目录订阅 effect 跟踪
   `current`——重置→effect 重建流→新流再发 `server.connected`→再重置，形成
   无限重订阅循环（~70 次/秒）。移除 project 桶重置（syncAll 本就整体重放
   project 列表与 current），1 个连接稳定。L2 测试 mock 了订阅层，未覆盖该
   路径。另记录：re-sync 的整表替换与同步窗口内事件的竞态在真实服务器上
   同样存在（影响面小，事件在后续刷新中自愈）。
